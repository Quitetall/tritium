# 0001 — Wire split-KV attention into the resident M=N decode  (serves: v0.4.1 / ADR 0013)

## Goal

The flash-decoding kernels `gqa_attention_split_partial_f32` + `gqa_attention_combine_f32` exist
and are gated correct (commit `b5173e9`), but the resident decode still calls the slow
`gqa_attention_mdecode_f32` (the N=1 bottleneck: 3 blocks, SM 0.2% busy). Replace it in **both**
M=N launch sites — `md_attn` (eager `decode_batch`) and `gb_attn` (graph `decode_batch_graph`) —
so the production batched decode uses split-KV. **Success criterion:** the existing bit-exact gate
`cuda_batch_decode_graph_matches_eager` stays green (both sites use the same kernels, so
graph==eager exactly), the greedy/parity gates stay within tolerance, and `batched_throughput`
N=1 graph rises from ~108 toward/past 142 tok/s.

**Scope note:** only the **M=N** path changes. The **M=1** resident decode (`step_graph`/`g_layer`,
which uses `gqa_attention_decode_warp_g` — a different kernel) is **untouched**. Do not edit
`g_attn`, `g_layer`, or the M=1 attention.

## Preconditions

- Branch `main`; `git log --oneline -1` shows `9e70354 fix(v0.4.1): assert head_dim<=256 ...`
  (or later). `git status` clean.
- The split-KV kernels + the `attn_split_kv_matches_direct_attention` gate are already committed.
- GPU free (`nvidia-smi` shows <2 GB used). If a `lamu`/`llama-server` holds VRAM, stop it first.

## Design (read before editing)

- **Graph-safe fixed grid.** A captured CUDA graph bakes launch grid dims, but `ctx` grows every
  step, so the split count must NOT depend on `ctx`. Use a **fixed chunk size** `CHUNK = 64` keys;
  the split count is `S = max_ctx.div_ceil(CHUNK)` — constant for the model's life → the graph's
  grid is valid for every step. Splits whose chunk starts past the current `ctx`
  (`start >= ctx`) write an identity partial (`m=-inf`) and are skipped in combine — the kernels
  already handle this. So at small `ctx` only the first few of `S` blocks do work; the rest return
  immediately (cheap).
- **Two launch sites, same kernels** → eager and graph stay **bit-identical** (the gate enforces it).
- **Partials scratch** `[n · n_head · S · (head_dim+2)]` lives on `BatchKv` (the M=N state); it
  replaces the per-call use of `d_scores` in the attention step (M=N only).
- Add a const: `const ATTN_SPLIT_CHUNK: usize = 64;` near the other kernel consts.

## Step 4 — Rewrite `md_attn` to launch the split-KV pair (eager M=N)

`md_attn` (~line 4842) currently launches one kernel `f` with a `scores` scratch. Replace its body
to launch the partial then combine kernel, using a `partials` scratch. Change its **signature** to
take `f_partial`, `f_combine`, and `partials` instead of `f` and `scores`.

- **File:** `crates/tritium-cuda/src/cuda.rs`
- **Replace** the whole `fn md_attn(…) { … }` (from `fn md_attn(` to its closing `}`) with:
  ```rust
      #[allow(clippy::too_many_arguments)]
      fn md_attn(
          s: &Arc<CudaStream>,
          f_partial: &CudaFunction,
          f_combine: &CudaFunction,
          q: &CudaSlice<f32>,
          k: &CudaSlice<f32>,
          v: &CudaSlice<f32>,
          out: &mut CudaSlice<f32>,
          partials: &mut CudaSlice<f32>,
          positions: &CudaSlice<i32>,
          max_ctx: usize,
          n_head: usize,
          n_head_kv: usize,
          head_dim: usize,
          scale: f32,
          n: usize,
      ) -> Result<(), BackendError> {
          let n_split = max_ctx.div_ceil(ATTN_SPLIT_CHUNK);
          let (mc_i, nh_i, nhkv_i, hd_i, n_i, ns_i, ck_i) = (
              max_ctx as i32,
              n_head as i32,
              n_head_kv as i32,
              head_dim as i32,
              n as i32,
              n_split as i32,
              ATTN_SPLIT_CHUNK as i32,
          );
          // Partial: one warp (32 threads) per (row, head, split).
          {
              let cfg = LaunchConfig {
                  grid_dim: ((n * n_head * n_split) as u32, 1, 1),
                  block_dim: (32, 1, 1),
                  shared_mem_bytes: 0,
              };
              let mut l = s.launch_builder(f_partial);
              l.arg(q).arg(k).arg(v).arg(partials).arg(positions).arg(&mc_i).arg(&nh_i)
                  .arg(&nhkv_i).arg(&hd_i).arg(&scale).arg(&n_i).arg(&ns_i).arg(&ck_i);
              // SAFETY: matches `gqa_attention_split_partial_f32(q, k, v, partials, positions,
              // max_ctx, n_head, n_head_kv, head_dim, scale, n, n_split, chunk)`; only `partials`
              // mutable; partials is `n·n_head·n_split·(head_dim+2)`; grid covers n·n_head·n_split warps.
              #[allow(unsafe_code)]
              unsafe { l.launch(cfg).map_err(|e| driver_err("launch md split partial", &e))?; }
          }
          // Combine: one warp per (row, head).
          {
              let cfg = LaunchConfig {
                  grid_dim: ((n * n_head) as u32, 1, 1),
                  block_dim: (32, 1, 1),
                  shared_mem_bytes: 0,
              };
              let mut l = s.launch_builder(f_combine);
              l.arg(&*partials).arg(out).arg(&nh_i).arg(&hd_i).arg(&n_i).arg(&ns_i);
              // SAFETY: matches `gqa_attention_combine_f32(partials, out, n_head, head_dim, n, n_split)`;
              // only `out` mutable; out is `n·n_head·head_dim`; grid covers n·n_head warps.
              #[allow(unsafe_code)]
              unsafe { l.launch(cfg).map_err(|e| driver_err("launch md split combine", &e))?; }
          }
          Ok(())
      }
  ```

          &self,
          q: sys::CUdeviceptr,
          k: sys::CUdeviceptr,
          v: sys::CUdeviceptr,
          out: sys::CUdeviceptr,
          partials: sys::CUdeviceptr,
          positions: sys::CUdeviceptr,

          let n_split = self.max_ctx.div_ceil(ATTN_SPLIT_CHUNK);
          let (mc_i, nh_i, nhkv_i, hd_i, n_i, ns_i, ck_i) = (
