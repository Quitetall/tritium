# Community channels and moderation

GitHub issues and pull requests are Tritium's only active project discussion
surfaces. No Discord server, GitHub Discussions forum, social account, or chat
room is official unless this file and the repository navigation link to it.

## Activation requirements

A new project-controlled channel requires explicit maintainer authorization,
named moderators in at least two time zones where practical, a private conduct
reporting route, retention/export capability, and a pinned link to the
[Code of Conduct](CODE_OF_CONDUCT.md). Activation is recorded in an ADR or pull
request; creating an account or namespace does not make it official.

## Moderation and escalation

Moderators may hide harmful content, slow or lock a discussion, and temporarily
restrict participation while a report is assessed. Credible threats, doxxing,
exploitation, or imminent harm are escalated immediately to the service provider
and appropriate emergency or legal channel. Security reports move to the private
process in [SECURITY.md](SECURITY.md). Other conduct appeals go to a moderator
who was not involved in the original decision when one is available.

Warnings, restrictions, bans, appeals, and reversals are recorded in a private
moderation log with minimum necessary personal data. Access is limited to active
moderators. Records are reviewed annually and deleted when no longer needed for
safety, legal, or repeat-abuse handling.

## Durable archive

Chat is not an architecture, support, benchmark, or release record. Decisions,
accepted proposals, reproducible answers, and evidence links must be summarized
in a GitHub issue, pull request, ADR, or repository document. If a third-party
channel closes, moderators export only content permitted by its terms and
privacy commitments; otherwise the repository record remains authoritative.
