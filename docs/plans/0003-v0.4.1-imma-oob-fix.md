# 0003 — Fix the JIT IMMA tail-shape OOB read  (serves: v0.4.1 / U7)

## Goal

`compute-sanitizer memcheck` flags `Invalid __global__ read` in `tq2_0_imma_mpgemm` on tail shapes
(test `imma_handles_tail_shapes`) — reads 1–2 bytes past the packed weight buffer. **Root cause
(verified by the planner):** the **JIT** IMMA kernel (generated by `crates/tritium-cuda/src/codegen.rs`;
it shares the symbol name `tq2_0_imma_mpgemm` with the AOT kernel) computes
`nt = blockIdx.x * N_SUBTILES + nn`. When an autotuned `tile_n > IMMA_N` (so `N_SUBTILES > 1`) and `N`
is not a multiple of the tile, the high sub-tile `nt` exceeds the buffer's `num_ntiles = ⌈N/IMMA_N⌉`
n-tiles → OOB read. The weight-stage loop guards `kt < num_ktiles` but **not** `nt`.

The **AOT** kernel (`kernels/tq2_0_imma.cu`, `nt = blockIdx.x`, grid `⌈N/IMMA_N⌉`) is in-bounds —
**do not edit it.** The fix is one guard in the JIT codegen; the kernel already receives `n`, so no
new parameter is needed. The padding tile's else-branch already writes zeros, so the fix changes no
result (those n-columns are masked on output write). **Success:** `compute-sanitizer memcheck` clean
on the full cuda test suite; the IMMA correctness tests still pass.

## Step 1 — Add the `nt` bounds guard to the JIT weight-stage loop

- **File:** `crates/tritium-cuda/src/codegen.rs`
- **Edit:** in the `stage` lambda's B-tile (weights) loop, the read is guarded only by `kt`. Find this
  exact line (~line 185):
  ```rust
              if (kt < num_ktiles) {{
  ```
  Replace it with (add the `nt` bound; `IMMA_N` is `#define`d in the generated source and `n` is a
  kernel param — the logical N used for output masking):
  ```rust
              if (kt < num_ktiles && nt * IMMA_N < n) {{
  ```
  **Context to confirm you're at the right line:** a few lines above is
  `const int nt = blockIdx.x * N_SUBTILES + nn;` and the body reads
  `weights[tile_byte0 + byte_in_tile]`; the matching `else {{` a few lines below writes
  `codes[j] = 0;`. This is inside a Rust raw/format string that generates CUDA, so the braces are
  doubled (`{{`/`}}`) — keep them doubled.
- **Command:** `cargo build -p tritium-cuda --features cuda 2>&1 | tail -3`
- **Expected (PASS):** `Finished`.
- **If you see `error: ... 'n' ... not declared` (in a CUDA build-script error, not Rust):** the JIT
  kernel's logical-N param is named something other than `n` — run
  `grep -nE "int (n|n_logical|N)[,)]" crates/tritium-cuda/src/codegen.rs` near the kernel signature
  (the `__global__ void ... tq2_0_imma_mpgemm(` line ~117) and use that param name. STOP and report
  if unclear.
- **If you see a Rust `error` about format string / unmatched brace:** you collapsed a `{{`/`}}` —
  restore the doubled braces.
- **Paste:** last 3 lines.
