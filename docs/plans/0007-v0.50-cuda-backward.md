# 0007 — CUDA backward kernels for the ternary matmul, gradient-checked vs the CPU vjp (single-GPU)  (serves: v0.50 / ADR 0007, Gate C on CUDA)

## Goal

Bring ADR 0007 **Gate C to the GPU**: f32 backward kernels for the ternary matmul
(`gA`, `gW`, `gs`) that match the `tritium-train` CPU `vjp` oracle on a real device, and
are `compute-sanitizer --tool memcheck` clean. **Single-GPU** (RTX 4090, sm_89).

**Success:** `cargo test -p tritium-cuda --features cuda train_backward_matches_cpu_vjp`
green on GPU; `compute-sanitizer --tool memcheck` 0 errors; `clippy -p tritium-cuda
--features cuda -- -D warnings` clean; `fmt --check` clean; default (no-cuda) build intact.

## Design notes (load-bearing; carry to 0008/0010)

1. **The training backward is f32, not the int8 IMMA inference path.** Gradients are
   continuous: `gA = Σ_n gY·s·W` with `W` real-valued (ternary in the QAT value path, or the
   STE surrogate in the gradient-checked path). So these are plain f32 contraction/reduction
   kernels — *not* the tensor-core `mma.m16n8k32` forward. Correctness > speed for v0.50;
   tiling/tensor-core backward is a later (v0.60+) optimization.

2. **One thread per output, sequential reduction, NO atomics ⇒ deterministic.** Each `gA[m,k]`
   / `gW[n,k]` / `gs[n]` is computed by exactly one thread looping the reduced dim. Work
   distribution can never reorder a sum, so the result is bit-stable. Atomics in a reduction
   would break that — avoided.

3. **`--fmad=false` ⇒ host bit-parity.** The kernels are compiled `--fmad=false` (same as the
   decode kernels) so `(gy*s)*w` and `+=` are not fused into one rounded `fma`; combined with
   matching the CPU vjp's reduction order and left-to-right multiply grouping element-for-element,
   the GPU result equals the CPU `vjp` to ~bit (the 1e-4 bar is a safety net, not a crutch).

4. **`GemmShape` API + checked launch bounds.** Host methods take `GemmShape` (bundling m/n/k,
   the crate convention) and validate that the device-side flat-index products (`m*n`, `n*k`,
   `m*k`, all formed as `int32` on device) fit `i32` — returning `BackendError::InvalidInput`
   rather than silently truncating the `as i32`/`as u32` casts. The `grad_a`/`grad_w` thread
   index is widened to `long`; the bound check makes the `int` inner index arithmetic safe too.

## Backward formulas (device == CPU vjp; ADR 0007 spine)
`gA[m,k] = Σ_n gy[m,n]·s[n]·W[n,k]` · `gW[n,k] = Σ_m gy[m,n]·s[n]·A[m,k]` ·
`gs[n] = Σ_m gy[m,n]·(Σ_k A[m,k]·W[n,k])`. Identical reduction orders to `tritium_train::ops::matmul::vjp`.

cargo test -p tritium-cuda --features cuda train_backward_matches_cpu_vjp -- --test-threads=1

Parity bar `Tolerance{relative:1e-4}` over 7 shapes incl. tails (1×1×7, 16×8×33, 5×7×1) and
N=300 (so `grad_s`'s own grid spans >1 block). All passed on the 4090; memcheck 0 errors.

## Review  *(planner)* — outcome recorded
Three independent lenses (kernel-math, host/cudarc, gate-validity).
- **kernel-math: PASS** — indexing correct, reduction order/grouping matches CPU bit-for-bit
  (verified, not tolerance-masked), no races/atomics, degenerate shapes (k=0, m=0, 1×1×1) safe,
  `__restrict__` sound (distinct allocations).
- **host/cudarc: PASS-WITH-NITS → fixed** — arg order matches each kernel signature (parity is
  real, not lucky); unsafe scoping, module lifetime, feature gating, `GemmShape: Copy` all
  correct. Nit (latent overflow on shapes ≥2³¹) → **fixed** with `check_grad_launch_bounds`.
  `alloc_zeros` dead-weight is harmless + matches convention (left as-is).
- **gate-validity: PASS-WITH-NITS → addressed** — non-vacuous (grads O(1–6)), oracle is
  independently FD-grounded in 0005/0006 (GPU-vs-CPU + CPU-vs-FD = GPU-correct), multi-block
  grids exercised (grad_a 3 blocks, grad_w 2 blocks; added N=300 so grad_s spans blocks too),
  1e-4 has teeth (relative branch engaged at |grad|>1). Known CI note: the GPU tests self-skip
  (green-but-skipped) on a cpu-only lane — fine here (ran on real GPU); a require-CUDA guard on
  the GPU lane is a CI-config follow-up, not a code change.

GPU parity test green; memcheck 0 errors; clippy/fmt clean; no-cuda build intact. The three
backward kernels match the CPU `vjp` oracle on device. **Deferred to the QAT loop (0010):** wire
