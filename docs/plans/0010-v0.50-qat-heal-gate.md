# 0010 — QAT heal loop + layerwise-recovery convergence gate → tag v0.5.0  (serves: v0.50 / ADR 0007)

## Goal

Close the last ADR 0007 DoD item — a QAT convergence smoke on the **real** BitNet-2b4t model —
then **tag `v0.5.0`** (the SemVer release; "v0.50" is the roadmap's old-staircase milestone label).

**Final gate (after the empirical findings below):** the QAT machinery (optimizer + STE + tape,
on real model activations) recovers **≥90% of an under-bitted attention slice's layerwise
distillation loss**; loss decreases; no NaN. Full-model perplexity is **reported as context**, not
gated — see finding #4.

## What actually happened — four GPU runs, four BitNet-specific walls (write-down)

The originally-planned "≥90% PPL recovery vs a naive-quant gap" turned out to be **statistically
void on this model**, for reasons that are properties of BitNet-2b4t, not the training core. Each
run isolated one:

1. **Single-layer naive-quant gap is sub-noise (~0.6% PPL).** BitNet's bf16 master IS the QAT
   shadow, so naive per-row ternary of it ≈ the deployed model — nothing to "heal." (run 1)
2. **No usable fp16 ceiling.** The bf16 master is the *latent* weight; run densely it scores
   ~garbage (~100× worse than the deployed ternary) — the repo's own `salt_accuracy.rs` documents +
   asserts this. So a "vs fp16" gap can't be measured. (investigation)
3. **The latent is per-TENSOR-QAT-trained.** `tritium-train`'s per-row STE reconstructs the
   unusable latent → garbage (per-row q_proj 8.76 vs per-tensor 1.40). Fix: broadcast a per-tensor
   absmean scale (`vec![absmean(W); n]`). (run 3)
4. **Layerwise distillation is underdetermined.** Fitting a 2560-wide layer from a 262-row eval
   slice → the optimizer fits the rows but drifts in the null space → rounds badly → full-model PPL
   does **not** follow from layerwise-loss convergence (per-tensor run: layerwise loss 4.55→0.25 =
   95%, but full-model PPL didn't recover). A real model-wide PPL recovery needs full-model
   backprop (v0.60), not layerwise distillation. (run 4)
   - Also (run 2): initializing the latent at the 1-bit grid (`|Wf/s_q|≈1`) freezes the STE mask —
     every gradient zeroes. Init from the spread master latent.

These are recorded in memory (`bitnet-2b4t-qat-recovery-gotchas`) and below.

## The gate (under-bitting → QAT layerwise recovery)

Reference = the deployed model (the only usable high-quality reference on this model). Per-tensor
everything (BitNet's granularity). Per-layer q/k/v inputs derived from `forward_dump.hidden_states`
+ an inline rmsnorm (matches `ops::rmsnorm`) — **no activation-capture hook needed**.

1. Load GGUF → runner. **Good**: install per-tensor-ternary(master) for the slice (q/k/v of the
   first `SLICE_LAYERS=6` layers); `ppl_good ≈ 1.40`.
2. **Degrade**: under-bit the slice to **1-bit** (sign-only, per-tensor scale); still ternary-
   representable so the resident decoder stays valid. `ppl_degraded ≈ 3.2`; guard asserts the gap
   is real (`> 2% of good`).
3. **Heal** each slice projection: latent `Wf = master` (spread → STE gradients flow); per-tensor
   `s_q = vec![absmean(Wf); n]`; tape `t = ste_surrogate(Wf,s_q)`, `y = matmul(X_train,t,s_q)`,
   `loss = mse(y, target)` where `target = dense(X_train, per-tensor-ternary(master))`; AdamW step.
   Accumulate per-projection first/last loss.
4. **Gate**: `layerwise_recovery = (Σfirst − Σlast)/Σfirst ≥ 0.90` (measured ~94.6%); loss
   decreases; every step finite. Re-quantize + `replace_weights` (exercises the bridge); report
   `ppl_healed` + the (underdetermined) full-model PPL recovery as context.

## Bridge (the only new model code — small, as predicted)
- `TernaryLinear::replace_weights(backend, &trits, scales)` + a shared `pack_rows` helper (`linear.rs`).
- `Projection::as_ternary_mut` (`projection.rs`).
- `ModelRunner::invalidate_resident` (`runner.rs`) — drops the cached resident decoder so a
  post-swap forward rebuilds from the new weights (without it, PPL reads stale device weights).
- `tests/qat_heal_gate.rs` — the GPU+model-gated integration test (self-skips otherwise).
- `tritium-train` as a `tritium-nn` dev-dependency.

## Review *(planner)* — to record after execution
Lenses: (1) gate honesty — is the layerwise recovery non-vacuous (negative-control: 0 steps → 0%),
and is the PPL "context" reported truthfully (the gap is real; full-model recovery is underdetermined,
not hidden)?; (2) `replace_weights`/`invalidate_resident` correctness (TQ2_0 re-pack round-trips; no
stale resident); (3) per-tensor-scale correctness (matches BitNet's granularity; the matmul applies
`scales[n]·Σ trit·x`).
