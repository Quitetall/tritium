# 0013 — GPU training step + pretrain smoke + LR schedule (serves: v0.60 / ADR 0008)

## Goal

The ADR 0008 "from-scratch tiny model reaches target loss" gate, on the single 4090: wire the
(currently dead-code) `train_grad.cu` `grad_a/grad_w/grad_s` kernels into a real **multi-leaf QAT
training step**, add an **LR schedule**, and train a **tiny from-scratch ternary model** to a target
loss on the GPU — with the device backward proven equal to the CPU tape vjp.

**Success:** `cargo test -p tritium-train` (LR schedule, CPU) + `cargo test -p tritium-cuda
--features cuda` (device step == CPU tape; pretrain smoke reaches target loss; no NaN) green;
`clippy -D warnings` + `fmt --check` clean.

## Scope decision (infancy / minimal-clean)

The plan-0008 row called this the "GPU-resident full-model training loop." A code-grounded look says
the *gate* ("tiny from-scratch model reaches target loss") is met by a **tiny** model — and the full
2B-parameter **resident** training engine (rebuilding the inference-only `CudaDecodeModel` for
training: arbitrary seq, activation retention/checkpointing, device-resident backward) is a large,
separate effort, bigger than the ≥2-GPU wall. We follow the established precedent — 0011 backpropped a
*tiny* transformer (not the 2B model); 0010 deferred full-model PPL recovery — and scope 0013 to the
**tiny GPU pretrain smoke**. The full-2B resident training forward is **deferred and documented** (a
later milestone), not attempted here.

Likewise, **activation-retention / dropping per-call htod↔dtoh** (the round-trip the grad bindings do
today) is a *performance* refinement whose value is immaterial at smoke scale. Per the
benchmarking-discipline standing memo (measure; "no win" is valid), 0013 implements the clean step on
the existing host-slice grad functions, **measures** the round-trip cost at smoke scale, and records
whether a device-resident-activation path is worth building (it becomes load-bearing only at 2B scale,
behind the deferred resident-training wall).

## Design

The CPU tape (`tritium-train`, validated in 0011) is the **trusted reference** for the QAT math. 0013
runs the *same* tiny model with the ternary-matmul forward + backward executed on the GPU via the
existing kernels, and gates the GPU path against the tape.

- **`LrSchedule`** (`tritium-train/src/lr.rs`, pure CPU, no unsafe): linear **warmup** (0→peak over
  `warmup` steps) then **cosine decay** to `min_lr` over the remaining `total` steps. `lr(step)->f32`,
  a pure function — reusable by any loop, TDD-able on CPU, decision-independent.
- **GPU QAT training step** (`tritium-cuda/src/train.rs`, behind `#[cfg(feature="cuda")]`; promote
  `tritium-train` to a real cuda-gated dep): a tiny **2-layer ternary MLP**
  `x → [Wq₁·,s₁] → squared-ReLU → [Wq₂·,s₂] → MSE` over synthetic data.
  - **Master weights** are f32 (init small-random, *not* on the 1-bit grid — avoids the STE-freeze,
    plan 0010 + the bitnet-qat-recovery memo); per-tensor scale `s` is a **learned leaf** (a clean
    QAT variant — exercises `grad_s` in the optimizer without the AbsMean-coupling subtlety).
  - **Forward:** STE-quantize `master→{-1,0,+1}` with `s`; ternary matmul on the GPU
    (existing forward); squared-ReLU on host (tiny).
  - **Backward:** MSE grad (host) → `grad_w`/`grad_s` for layer 2 + `grad_a` to reach the hidden
    activation → squared-ReLU vjp (host) → `grad_w`/`grad_s` for layer 1. All three kernels exercised,
    both layers. STE maps the weight grad to the master (`·(1/s)·[|master/s|≤1]`).
  - **Optimizer:** the existing `AdamW` steps each leaf (`W₁,W₂` masters + `s₁,s₂`), lr from
    `LrSchedule`.

## Gates
- **LR (CPU):** `lr(0)` respects warmup floor; `lr(warmup)==peak`; cosine monotone-decreasing on
  `[warmup,total]`; `lr(total)≈min_lr`; `lr` never NaN/negative; golden values at a few steps.
- **device step == CPU tape:** one full train step's gradients for every leaf match the `tritium-train`
  tape vjp within `≤1e-4` (extends the existing `train_backward_matches_cpu_vjp`, which already covers
  the bare matmul grads, to the composed 2-layer step).
- **pretrain smoke:** from a seeded init the MSE loss drops below an observed target over the step
  budget (the convergence gate — target set from observed behavior, like 0010), strictly decreasing in
  trend, **no NaN/Inf** at any step.
- **clippy `-D warnings` + `fmt --check`** clean. `compute-sanitizer` on the GPU test if available
  (record result; not a hard gate if the tool is absent — none is wired in the repo today).

## Design notes
- Reuse: `AdamW` + `Optimizer` (`optim.rs`), the STE-quantize + matmul vjp (`tritium-train::ops`) as
  the oracle, `grad_a/grad_w/grad_s` (`cuda.rs:551-757`) + the ternary forward, `seeded_f32`
  (testkit). Determinism: seed every init + the synthetic data so the smoke is reproducible.
- STE-freeze avoidance is load-bearing (6 GPU runs' worth of scars, see the bitnet-qat memo): init
  master off the grid, scale via a value that spreads `|master/s|` around — *not* pinned at 1.

## Done criterion
LR-schedule + device-step-equals-tape + pretrain-smoke gates green; clippy/fmt clean; round-trip cost
measured + recorded. The dead-code grad kernels are now wired into a converging GPU training step.
The full-2B resident training engine is documented as deferred. Ships on the `0.5.x` line.

## Outcome — done (tagged `v0.5.3`)
All gates green. `LrSchedule` (`tritium-train`, CPU): 6 tests (warmup ramp, peak boundary, monotone
cosine decay, clamp-past-total, degenerate `window==0`, proptest finite/bounded — now reaching
`warmup==total`). The new `ternary_matmul_forward` kernel + `train_forward` binding wire the formerly
dead-code `grad_a/grad_w/grad_s` into a GPU QAT step for a 2-layer ternary MLP (learned per-row scale;
master updated through `ste::quantize_vjp`). Gates: **device step == CPU tape** ≤1e-4 (composed);
**pretrain smoke** loss `0.261 → 0.025` (**90.5% drop**, gated `<0.30`), no NaN, `0.98 ms/step`;
`clippy -D warnings` + `fmt` clean; **`compute-sanitizer` memcheck: 0 errors**; full 45-test cuda suite
green, default no-CUDA build inert.

Adversarial multi-lens review (24 agents) — confirmed findings fixed before the tag:
- **MAJOR (verification gap):** the device==CPU gate runs the *same* `forward_backward` on both
  engines, so a coherent miswiring (e.g. `relu2_vjp(h)` vs `(h_pre)`) passes it. Added a CPU
  finite-difference gradcheck of the composed weight-master gradients against the smooth STE-surrogate
  loss (`forward_backward` parameterized by the quantizer). **Mutation-verified:** injecting that exact
  miswiring fails the new gate (90% off) while device==CPU still passes — the gate has teeth.
- **MAJOR:** AdamW weight-decay (0.01) was shrinking the *learned scale* leaves toward 0 against
  `grad_s`. Scales now use a `weight_decay: 0.0` optimizer (the `qat_heal_gate.rs` idiom).
- Plus: corrected the inaccurate "LSQ-style" doc (it's a learned output gain, quantizer-scale
  stop-gradiented — not LSQ); restored grad_a's doc + removed the now-stale `#[allow(dead_code)]` on
  the wired kernels; a `k==0` guard on `train_forward`; the LR proptest reaches `window==0`.

Measured: the smoke does 4 round-tripped matmuls/step at ~0.25 ms each — confirming activation-
retention (dropping the per-call htod↔dtoh) is immaterial at this scale, deferred with the full-2B
resident training engine. The layer-1 `grad_a` (`dL/dx`, discarded) is likewise a documented,
deferred micro-waste (keeps the symmetric `GemmEngine` abstraction that serves both engines).
