# 0016 — Distributed checkpoint + resharding + fault injection (serves: v0.60 / ADR 0008)

## Goal

The ADR-0008 "checkpoint resharding `J≠K` ⇒ identical forward; resume continues" and "kill rank
mid-run ⇒ clean error / no corrupt checkpoint" gates, reachable on one machine: a sharded distributed
checkpoint (DCP) over the [`FlatShardPlan`](../../crates/tritium-train/src/fsdp.rs) layout (0015) with
crash-atomic writes, so a checkpoint saved with `K` shards loads + reshards to any `J` with an
identical forward, a mid-run save+restore continues the loss curve bit-exactly, and an interrupted or
corrupted save never replaces or silently loads a torn checkpoint.

**Success:** `cargo test -p tritium-train` green incl. the DCP gates (byte-framing round-trips;
save-K/load-J round-trip identity + identical forward; distributed bit-exact resume; interrupted-save
/ truncated-shard / missing-shard / corrupt-manifest fault detection); `clippy -D warnings` +
`fmt --check` clean.

## Where it lives (infancy / minimal-clean)

In **`tritium-train`** as a `dcp` module next to [`fsdp`](../../crates/tritium-train/src/fsdp.rs) and
[`checkpoint`](../../crates/tritium-train/src/checkpoint.rs). It reuses the never-panic `Cursor` +
little-endian framing from `checkpoint` (a `pub take_magic` was added there) — a distributed checkpoint
is the *sharded, on-disk, crash-atomic* sibling of the single-buffer `TOPT` checkpoint, not a new
format family. The shard layout is exactly `FlatShardPlan`'s, so the DCP is the natural consumer of
0015's descriptor; no new sharding logic.

The library does real file I/O here (unlike `checkpoint`, which is pure serialization the caller
writes), because **the atomicity is the point**: temp-write → `fsync` → `rename` → `fsync` parent dir.
Byte framing (`serialize_*`/`parse_*`) stays pure + unit-tested; `save`/`load` are the thin I/O layer.

## Design

A distributed checkpoint is a **directory**:
```text
<dir>/manifest.tdcp                       ← the commit point (written/renamed LAST)
<dir>/step_<step>_shard_<rank:04>.tdcp    ← one per rank at save time
```

- **World-agnostic global state.** A shard is just a contiguous slice of the flattened-and-padded
  global buffers ([`FlatShardPlan`]). The optimizer state rides as **parallel f32 planes** aligned with
  the flat parameter (AdamW → `[m, v]`), sharded by the *same* element range — so the DCP is
  optimizer-agnostic (`n_planes` in the manifest), and [`load`] reassembles the same global
  `(param, planes, step)` **regardless of the save-time world `K`** (concatenation is a copy).
  **Resharding** to a new world `J` is then just `FlatShardPlan::new(leaf_lens, J)` applied by the
  caller — there is no separate reshard codepath.

- **`DistCheckpoint`** (the global contents): `step`, `leaf_lens` (the flat layout), `param`
  (length `Σ leaf_lens`), `planes` (each the same length). `save(dir, &ckpt, world)` flattens+pads,
  writes one shard per rank, then commits the manifest; `load(dir)` reads the manifest, recomputes the
  plan from `leaf_lens + world`, reads every named shard, and reassembles the global (padding dropped).

- **Crash atomicity (no torn checkpoint).** Every file is written to a `.tmp` sibling, `fsync`ed,
  `rename`d into place (atomic on POSIX), and the parent dir is `fsync`ed for durability. **Shards are
  committed first, the manifest last** — the manifest is the single commit point. A crash before the
  manifest commits leaves the *previous* manifest + its complete shards intact; `load` reads only what
  the live manifest names, ignoring half-written `.tmp` files and orphaned shards. A committed manifest
  therefore only ever names fully-written shards; an *externally* truncated shard is caught by the
  length check and returns a [`DcpError`] rather than loading garbage.

- **Validation (never-panic on untrusted bytes).** Manifest + shard magic/version; each shard's header
  (`step`/`world`/`rank`/`n_planes`/`shard_len`) is checked against the manifest (stale / mismatched /
  wrong-rank shard → `ShardMismatch`); a missing shard → `MissingShard`; a manifest whose `total`/
  `chunk` disagree with the plan recomputed from `leaf_lens+world` → `LayoutMismatch`; truncation /
  trailing bytes → `Truncated` / `TrailingBytes`. Caller-supplied length mismatches in `save` are
  `assert`s (a programming error, matching the codebase's assert-on-misuse convention).

## Gates
- **Byte framing (inline unit):** manifest + shard round-trip; bad-magic / trailing-bytes / truncation
  / stale-step / wrong-rank all detected (never panic).
- **save-K / load-J:** the loaded global state is bit-identical for every save world `K∈{1,2,4}`
  (round-trip identity); resharding to every `J∈{1,2,4}` and reassembling reproduces the global param,
  and the forward (a concrete MLP loss) is identical for every `(K, J)`.
- **distributed resume (bit-exact):** train `HALF` steps on world `W∈{1,2,4}`, DCP-save mid-run,
  restore, continue — the resumed loss curve equals the uninterrupted curve **bit-for-bit** (same
  world). Proves the optimizer state (`m`, `v`) + step survive the round-trip exactly, not just params.
- **fault injection:** an interrupted save (orphan shard + uncommitted manifest `.tmp`) leaves the
  previously-committed checkpoint intact; a truncated shard → `Truncated`; a missing shard →
  `MissingShard`; a corrupted manifest → `BadMagic`. Never a panic, never a silent corrupt load.

## Design notes
- Reuse: `FlatShardPlan` (0015) for the shard layout; `Cursor`/`CheckpointError` + LE framing
  (`checkpoint`, 0008); the `thread::scope` FSDP loop (0015) for the resume gate; `AdamW`/`AdamState`
  (0008) → the two state planes. The resume gate's baseline (uninterrupted curve) is computed by the
  *same* FSDP loop with no save/restore — so the bit-exact compare is end-to-end.
- Resume bit-exactness is asserted **same-world** (save `W`, resume `W`): across worlds the pre-save
  steps already diverge by the data-parallel float reorder (0015), so a cross-world resume tracks only
  within tolerance — the resharding gate covers the cross-world dimension at the param/forward level.
- **Deferred (documented):** keep-last-N garbage collection of superseded shard files (a disk cost,
  not a correctness one); a real backend's distributed barrier around the commit (0017's NCCL job will
  add a rendezvous so all ranks agree the manifest is committed). Neither is expensive to retrofit.
