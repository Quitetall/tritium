## Design notes (load-bearing; carry to 0009/0010 and the v0.60 optimizer additions)

1. **The optimizer is tape-agnostic.** It steps plain `&mut [f32]` param buffers given their
   `&[f32]` grads (which `Tape::backward` returns per `ValueId`). Params (`Wf`, bias, later LoRA
   factors) are owned *outside* the tape; the QAT loop rebuilds the forward graph each step,
   extracts grads, and calls `step`. No `Tape` mutation API is needed. This matches how the
   toy-layer test already rebuilds a fresh tape per gradient eval.

2. **Minimal, clean trait — no speculative seams (project-infancy directive).** The codebase is
   young; changing a trait signature or bumping a versioned format is a *cheap* mechanical edit,
   so the trait expresses exactly what the optimizer that exists today (AdamW) needs and nothing
   more. In particular **`Shape` is NOT in the `step`/`init_state` signature.** A future 2D-aware
   optimizer (Muon) or a factored one (Adafactor) holds its own `rows`/`cols` as struct fields —
   shape belongs to the optimizer *instance* (configured per param-group), not threaded through
   every `step` call that AdamW would only ignore. Likewise **no `OptimKind` discriminator** is
   baked into the checkpoint for optimizers that don't exist; the format carries a `version` byte,
   and when a second optimizer arrives a discriminator is added then (cheap, versioned). (Optimizer
   landscape from the v0.50 study — Muon/Lion/Sophia/Shampoo/SOAP/AdEMAMix/Schedule-Free/Adafactor
   vs the *honest* matched-tuning benchmark arXiv:2509.02046, which collapses the famous 2× claims
   to ~1.1–1.4× — informs *what* lands later, not scaffolding baked in now.)

3. **Decoupled weight decay (the "W" in AdamW, Loshchilov & Hutter 2019).** The decay is applied
   to the parameter directly, *never folded into the gradient or the second moment*:
   `w ← w·(1 − lr·wd) − lr·m̂/(√v̂ + eps)`. (Algebraically identical to PyTorch's
   `param.mul_(1−lr·wd)` then `addcdiv_`.) `eps` sits *outside* the sqrt: `√v̂ + eps`, matching
   `torch.optim.AdamW`.

4. **Bit-exact resume is automatic from f32-LE round-trip + identical op order.** The checkpoint
   stores `m`, `v`, `t`, and the params as little-endian f32; f32 LE round-trips exactly, and the
   AdamW update is a fixed sequence of f32 ops on identical inputs, so `N` steps uninterrupted ==
   `N/2` + checkpoint + restore + `N/2`, bit-for-bit on the same machine. The round-trip test
   asserts **byte-equality of `write(read(write(x)))`** (sidesteps `NaN≠NaN`); the resume test
   asserts exact-f32 equality of the two final param/state vectors (no NaN on a converging loop).

5. **`t` is the 1-based completed-step count.** Bias correction at call `t` uses
   `1 − βᵗ`. The driver increments `t` once per `step_all`; the checkpoint stores the count of
   completed steps; the first post-resume step uses `t+1`.

6. **Never-panic, bounds-checked deserialization** mirrors `tritium-format::salt_bundle`'s
   discipline (magic + version + bounds-checked `Cursor`), but with a **local** `CheckpointError`
   + `Cursor` (keeps `tritium-train`'s deps at `tritium-core` + `tritium-testkit`, no `tritium-
   format` coupling — the checkpoint is not a SALT artifact).

## `TOPT` checkpoint layout (LE; never-panic, bounds-checked like `salt_bundle.rs`)
```text
magic b"TOPT" (4) | version u8
step u64
leaf_count u32
per leaf: len u64 | param[len] f32 | <optimizer state: AdamW = m[len] f32, v[len] f32>
```
`read_checkpoint::<O>` asserts magic + version; every field is read through the bounds-checked
`Cursor` (truncation ⇒ `CheckpointError::Truncated`, trailing bytes ⇒ `TrailingBytes`). `len` (an
element count) is all the deserializer needs — shape isn't a checkpoint concern because it isn't a
trait concern. A second optimizer (later) adds a discriminator behind a `version` bump.

## AdamW update (the spine; matches `torch.optim.AdamW`)
At step `t` (1-based), per element `i`, with `g = grad[i]`:
```text
m ← β1·m + (1−β1)·g ;  v ← β2·v + (1−β2)·g²
m̂ = m/(1−β1ᵗ) ;       v̂ = v/(1−β2ᵗ)
w ← w·(1 − lr·wd) − lr·m̂/(√v̂ + eps)
```
Closed-form test (t=1, wd=0): m̂=g, v̂=g² ⇒ `w ← w − lr·g/(|g| + eps)` (assert ≤1e-6).

## Scope boundary (deliberate; from the optimizer study)
**In v0.5.0:** the minimal `Optimizer` trait (no `Shape` in the signature — see design note 2),
AdamW, and the versioned `TOPT` checkpoint (no `OptimKind` discriminator yet). **Deferred, by design, with rationale recorded:**
- **Lion → v0.50.x** — cheapest second optimizer (1× state, sign update, decoupled WD); ship it
  to *prove the trait generalizes across differing state-buffer counts*.
- **Adafactor → v0.60** — factored 2nd moment; element-wise numerator preserves the STE zero-mask
  (the principled memory fallback for a full-`Wf` heal).
- **Muon → v0.60+, behind a flag, LoRA path first** — mechanically wrong on latent `Wf` (STE
  block-sparse grad ⇒ dense polar factor resurrects the saturated band); needs a net-new dense
  GEMM; gate behind the ≥90%-recovery test; tests must assert a flat singular-value band, NOT
  `OOᵀ=I`.
- **Sophia / Shampoo / SOAP** — not on the roadmap (Hessian meaningless through the STE surrogate;
  eigendecomp/matrix-root infeasible in safe Rust for the win).
- **Schedule-Free** — design-compatible (a wrapper adding one averaged-weight buffer) but defer
  until the "which buffer is the eval/projection model" threading through checkpoint + ternary
  projection is deliberate.
- **A generic heterogeneous param-group *router*, `Shape` in the trait signature, and an
  `OptimKind` checkpoint discriminator** — all NOT built now. The codebase is in its infancy;
  these are cheap, clean, versioned retrofits when a second optimizer actually exists. Building
  them now would only add speculative scaffolding the single current optimizer ignores.
