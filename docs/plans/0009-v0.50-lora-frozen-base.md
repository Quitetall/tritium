# 0009 — LoRA adapters on a frozen ternary base (single-node, CPU)  (serves: v0.50 / ADR 0007)

## Goal

Bring the ADR 0007 **LoRA** DoD bullet to green on CPU: low-rank adapters trained over a
**frozen** ternary base, where the base receives **zero** gradient, the adapter **merges**
correctly into a dense weight, and the **rank edges `r=1` and `r=full`** both pass —
validated by **proptest** (+ a Gate-C finite-difference gradient-check of the new trainable
op, since "every trainable op" is gradient-checked).

**Success:** `cargo test -p tritium-train` green incl. the LoRA proptests + gradient-checks;
`clippy -p tritium-train --all-targets -- -D warnings` clean; `fmt --check` clean.

## Design notes (load-bearing; minimal, modular — project-infancy directive)

LoRA is composed from **small reusable primitives**, not a fused op — each is independently
gradient-checkable and useful beyond LoRA:

1. **`dense` matmul op** — `Y[m,n] = Σ_k X[m,k]·W[n,k]` (`X:[M,K]`, `W:[N,K]` → `Y:[M,N]`),
   with `vjp → (gX, gW)`. This is the ternary `matmul` minus the per-row scale and minus the
   ternary semantics — a plain real-f32 contraction differentiable in both inputs. The LoRA
   delta is two of these composed.

2. **`detach` tape op (stop-gradient) — this is what *freezes* the base.** Forward is the
   identity; `vjp` returns **zeros**. Wrapping the base matmul output in `detach` means the
   base's leaves (`trits`, `scale`, or an upstream `Wf`) receive **exactly** zero gradient,
   while the adapter path trains. Clean, reusable, and the direct implementation of "frozen".

3. **`scale_const` tape op** — `Y = c·X` for a compile-time-constant scalar `c`; `vjp = c·g`.
   Carries the LoRA `α/r` scaling as an explicit differentiable node (no hidden pre-scaling of
   a trainable leaf).

4. **Layer forward** (the composition):
   `Y = add( detach(base_matmul(act, trits, scale)), scale_const(dense(dense(act, A), B), α/r) )`
   where `U = dense(act, A) : [M,r]` (A as `[r,K]` weights), then `ΔY = dense(U, B) : [M,N]`
   (B as `[N,r]` weights). Trainable leaves: **A, B only**.

5. **Merge** folds the adapter into one dense weight for inference:
   `W_merged[n,k] = scale[n]·trits[n,k] + (α/r)·Σ_j B[n,j]·A[j,k]`. Inference is then a single
   `dense(act, W_merged)`, bit-equal (within tol) to `base + adapter` — the merge-correctness gate.

6. **Rank edges.** `r=1` (minimal: `A:[1,K]`, `B:[N,1]`) and `r=full = min(N,K)` (the factorization
   can represent an arbitrary `[N,K]` delta) both train + merge correctly.

## Files
- `src/ops/dense.rs` — `forward(x, w, m, n, k)` + `vjp` (→ `[gX, gW]`). `#[allow(clippy::needless_range_loop)]` per the op convention.
- `src/ops/mod.rs` — `pub mod dense;`.
- `src/tape.rs` — `dense_matmul(x, w, m, n, k)`, `detach(x)`, `scale_const(x, c)` op-recording methods.
- `src/lora.rs` — `Lora { a, b, rank, n, k, alpha }`; `scaling() = α/r`; `delta_weights() → [N,K]`;
  `merge(base_dense) → [N,K]`; a `forward_loss`-style tape composition helper for the layer.
- `src/lib.rs` — `pub mod lora;` + re-export `Lora`.
- `Cargo.toml` — `proptest = { workspace = true }` in `[dev-dependencies]` (the workspace already pins it).
- `tests/lora.rs` — proptests: (a) frozen base → base grads **exactly 0**; (b) merge correctness
  (merged dense forward ≈ base + adapter) incl. `r=1`/`r=full`; (c) adapter gradient-check (A,B vs
  central FD, Gate-C tol) on fixed fixtures; (d) `r=1` and `r=full` both finite + correct.
- `tests/gradcheck_ste_matmul.rs` — add `dense_matmul_grad_wrt_x_and_w` (Gate-C FD check of the new op).

## Scope boundary (deliberate)
**In:** the `dense`/`detach`/`scale_const` primitives, the `Lora` adapter + merge, and the four
proptests/gradient-checks above. **Deferred:** wiring LoRA into the QAT heal loop (that is 0010);
a CUDA dense-backward kernel (v0.60 perf — the CPU path is the v0.50 correctness gate); LoRA
dropout / multiple-adapter composition (not in the ADR 0007 DoD).

## Review *(planner)* — outcome recorded
Four-lens adversarial review (each finding independently verified). Fixed before commit:
- **MAJOR (test vacuity): the merge proptest could not detect a wrong `delta_weights()`/`scaling()`.**
  Both compared sides routed through `delta_weights()`, and `dense` is linear in its weight, so the
  `α/r·BA` term cancelled — `dense(act, base+ΔW) == base + dense(act, ΔW)` for *any* ΔW. Fixed:
  `y_composed` now uses the **independent two-matmul `B·A` chain** with a literal `α/r`, so a wrong
  `scaling()` or `delta_weights()` index no longer cancels. Added `lora_delta_weights_matches_hand_
  computation` (integer ground truth: `scaling==2`, `ΔW==[46,68]`). **Negative-controlled:** mutating
  `scaling()` to `α·r` now fails both (it previously passed).
- **minor:** split the proptest's `adapter trains` OR into… reconsidered — *dropped* it instead: at
  `m=n=k=1` a random `act[0]=0`/`B[0]=0` legitimately zeros a factor's grad (not a freeze failure), so
  the property belongs in the deterministic gradient-check (which pins both A,B vs FD, neg-controlled),
  not a random proptest. The proptest keeps the always-true property: frozen-base grad **exactly 0**.
- **convention:** shape `assert_eq!` on `a`/`b` in `delta_weights()` (mirrors `merge`'s base assert)
  + `debug_assert!(rank>0)` in `scaling()`; added a direct `scale_const_forward_and_backward` test.
- Refuted/deferred: rank-edge coverage confirmed non-vacuous (`r=full` reachable); the `seeded`
  fixture duplication across test files is pre-existing and left for a separate hygiene pass.
- **Process note:** a review verifier mutated the working tree (dropped the base in `build_layer`,
  flipped `scaling()` to `*`) to test hypotheses; both were detected and reverted before commit — the
  committed tree was re-verified clean (no `SABOTAGE`/`NEG CONTROL` markers; full gate green).

Negative controls (all reverted): removing `detach` → frozen proptest fails; scaling `dense::vjp`'s
`gW` by 0.5 → gradient-check fails; `scaling()` → `α·r` → merge proptest + hand-computed test fail.
