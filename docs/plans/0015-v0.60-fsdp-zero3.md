# 0015 — ZeRO-3 / FSDP over the simulated `ProcessGroup` (serves: v0.60 / ADR 0008)

## Goal

The ADR-0008 "N-GPU vs 1-GPU loss-curve parity" gate, reachable on one machine: shard a tiny
model's parameters, gradients, and optimizer state across `world` simulated ranks (ZeRO-3 / FSDP),
**all_gather** params before the forward and **reduce_scatter** grads after the backward over the
[`SimProcessGroup`](../../crates/tritium-train/src/dist.rs) from 0014, and prove the resulting loss
curve matches a single-process full-batch reference — bit-exact where the float arithmetic permits it,
and within a measured tolerance where data-parallel grad summation reorders the floats.

**Success:** `cargo test -p tritium-train` green incl. the FSDP gates (flat-shard plan properties;
world=1 FSDP == baseline bit-exact; world=2 *replicated-data* FSDP == baseline bit-exact; data-parallel
partition parity within the recorded tolerance for `world∈{2,4}`; determinism under thread scheduling);
`clippy -D warnings` + `fmt --check` clean.

## Where it lives (infancy / minimal-clean)

In **`tritium-train`** as an `fsdp` module next to [`dist`](../../crates/tritium-train/src/dist.rs).
The library piece is exactly the reusable, load-bearing one: a **flat-parameter shard descriptor**
([`FlatShardPlan`]) — concatenate the trainable leaves into one flat buffer (real FSDP's
"FlatParameter"), pad to a multiple of `world`, split into `world` equal contiguous shards, and
flatten/unflatten between the leaf view and the flat view. That descriptor is the seed of the 0016
distributed-checkpoint manifest `(global_shape, local_offset, shard_spec)` — building it here is the
cheap, clean foundation 0016 reshards over.

The **training orchestration** (gather → forward/backward → reduce_scatter → optimizer step) is a
handful of lines and lives in the gate test, parameterized by the model's forward/backward closure —
deliberately *not* abstracted into a premature `fsdp_step` helper. The only consumer of an
orchestration helper would be the test itself (0016 needs the *plan*, not the step); a `fsdp_step`
seam is a cheap retrofit if a real training loop later wants one, and nothing here makes it expensive.

## Design

The CPU tape (`tritium-train`, gradient-checked in 0011) is the **trusted reference** for the model
math; AdamW (0008) is the optimizer. FSDP changes *where parameters and their grads/state live*, not
the math — so the parity gates compare an FSDP run against an independent, single-threaded full-batch
baseline that uses neither sharding nor collectives.

- **Model (the minimal vehicle).** A tiny dense 2-layer MLP — `x → [W₁·] → squared-ReLU → [W₂·] →
  MSE` — over seeded synthetic data, built on the already-gradient-checked `dense_matmul` / `relu2` /
  `mse` tape ops. **Dense f32, not ternary on purpose:** 0015's gate is distributed *parity*, not
  convergence, and quantization is orthogonal — FSDP shards a flat f32 master buffer identically
  whether or not the forward quantizes, and the ternary/QAT path is already gated by 0013. A dense
  model keeps the loss curve smooth, the flat-parameter layout uniform (one AdamW config, no learned-
  scale weight-decay subtlety), and the float-reorder tolerance interpretable.

- **`FlatShardPlan`** (the library piece). `new(leaf_lens, world)` records each leaf's `(offset, len)`
  in the flat buffer, the unpadded `total`, and `chunk = ceil(total / world)`; `padded_len = chunk *
  world`. `flatten(leaves) -> Vec<f32>` packs the leaves into a `padded_len` buffer (padding zeroed);
  `unflatten(flat) -> Vec<Vec<f32>>` returns only the real `[0, total)` region split back into leaves
  (padding is never read into a leaf). `shard_range(rank) = [rank*chunk, (rank+1)*chunk)`.

- **One FSDP step (per rank, in the test).** (1) `all_gather` the local param shard → the full padded
  flat buffer → `unflatten` → leaf params; (2) run the tape forward+backward on this rank's **local
  data slice** → per-leaf grads → `flatten` → padded flat grad; (3) `reduce_scatter(Avg)` the flat grad
  → this rank's `chunk`-sized grad shard; (4) `AdamW::step` on the **local param shard** with the local
  grad shard and the local (sharded) `AdamState`; (5) `all_reduce(Avg)` the scalar loss → the global
  loss for the curve. Params stay sharded between steps; only gathered transiently for the forward.

- **Single FSDP unit (whole-model gather), documented.** Real FSDP gathers/frees *per layer* to bound
  peak memory; that is a *memory* optimization invisible to the loss curve. 0015 uses one FlatParameter
  for the whole tiny model (one all_gather/step) — the minimal correct FSDP — and documents per-layer
  gather/free as the deferred memory win (it generalizes to one `FlatShardPlan` per unit; cheap
  retrofit). The 2B-scale resident memory engine is already fenced as deferred (0013).

## What each gate layer can prove (and what it cannot)

`f32` addition is non-associative, so *where* gradients are summed matters — but the subtler trap is
that **AdamW's update `m̂/(√v̂+ε)` is scale-invariant in the gradient**: scaling every gradient by a
constant `c` cancels in the adaptive normalizer (only the `ε` floor leaks, ~1e-8). So a loss/param
*curve* comparison **cannot** detect a `world`-times gradient error (e.g. `reduce_scatter` using `Sum`
instead of `Avg`). The gate is therefore layered, and the load-bearing teeth are at the **gradient**
level, not the loss level (an adversarial review caught this — the original loss-only gate was blind
to a wrong reduce op):

- **world=1 FSDP == baseline (bit-exact).** One shard = the whole flat buffer, `all_gather`/
  `reduce_scatter` are identity copies, the sharded AdamW step is the full step. Proves the FSDP
  orchestration is a faithful refactor of the plain loop (a coherent-miswiring guard — *different code*).

- **Replicated-data FSDP == baseline (bit-exact), `world∈{2,4}`.** Feed every rank the **same full
  batch**: each computes the identical full grad `G`; `reduce_scatter(Avg)` over `world` identical slots
  yields `ΣG/world`, which equals `G` **bit-exactly for `world∈{2,4}`** (empirically verified over 20 M
  random gradients: 0 non-exact). The intuition is *not* a clean "power-of-two world is safe" rule — the
  running sum `0+G+G+…` accumulates intermediate rounding (`3G` rounds), but for `/2` and `/4` that
  rounding happens to cancel, whereas **`world=8` is generally NOT bit-exact** (~35 % non-exact in the
  same sweep). AdamW is element-wise, so stepping the shard `[r*chunk, (r+1)*chunk)` reproduces the
  baseline's slice update bit-for-bit. This isolates the *sharding mechanics* (gather + reduce_scatter +
  sharded optimizer/state) from data-parallel reordering. (We assert only `{2,4}`; `world=8` would be
  within-tolerance.)

- **Reduced gradient == full-batch gradient (the teeth), `world∈{2,4}`.** Run one FSDP gradient
  reduction over a **partitioned** batch and compare the reassembled reduced gradient *directly* against
  the single-process full-batch gradient. Because this is not scale-invariant, it catches a wrong
  `ReduceOp` (off by exactly `world`), a dropped cross-rank reduction, or a wrong shard slice (off by
  ≥2×) — all far outside the ~1e-7 float-reorder tolerance. This is the gate that actually guarantees
  distributed gradient correctness; mutation-verified (injecting `Avg→Sum` fails it).

- **Data-parallel partition loss-curve tracking (within measured tolerance), `world∈{2,4}`.** With a
  mean loss and equal slices, `Avg`-reducing the per-rank mean-grads recovers the full-batch mean-grad
  *mathematically*, but per-rank partial sums reorder the float adds — so the end-to-end curve agrees
  only to a tolerance. We **measure** the max divergence (≈1 ULP, ~4.5e-8) and gate with margin (the
  0010/0013 "target from observed" discipline). This is a convergence-*tracking* check, **not** the
  wrong-reduce-op gate (that is the gradient test above) — stated honestly because Adam makes it blind
  to gradient scale.

## Gates
- **`FlatShardPlan` properties:** `flatten`→`unflatten` is identity on `[0, total)`; `shard_range`
  partitions `[0, padded_len())` into `world` equal chunks; `padded_len() >= total` with padding
  zeroed; the no-padding (`total % world == 0`) and padding (`world=4`, `total=42`) cases both hold.
- **world=1 FSDP == baseline:** identical loss curve **and** final params (bit-exact).
- **replicated == baseline, `world∈{2,4}`:** identical loss curve **and** final params (bit-exact).
- **reduced gradient == full-batch gradient (teeth), `world∈{2,4}`:** the reassembled reduced gradient
  matches the single-process full-batch gradient (partitioned: within ~1e-7; replicated: bit-exact).
  Not scale-invariant — catches a wrong `ReduceOp` / dropped reduction / wrong slice.
- **partition loss-curve tracking:** `world∈{2,4}` partitioned loss curves within the recorded
  tolerance (≈1 ULP) of the baseline over the budget — a convergence-tracking check, not the
  reduce-op gate.
- **determinism:** the FSDP loss curve is bit-identical across repeated runs (no thread-schedule
  dependence) — the fixed-order fold doing its job through a real training loop.

## Design notes
- Reuse: `dense_matmul`/`relu2`/`mse` tape ops (0011, gradient-checked) as the trusted model;
  `AdamW`+`AdamState` (0008); `SimProcessGroup`'s `all_gather`/`reduce_scatter`/`all_reduce` (0014);
  the `thread::scope` per-rank harness idiom (`tests/dist_collectives.rs`); the splitmix/xorshift seed
  idiom for init + data. Determinism: seed every init + the synthetic data so curves are reproducible.
- The baseline is an **independent** single-threaded full-batch loop (no sharding, no collectives) — so
  a coherent bug copied into both sides cannot pass the gate (the 0013 review's verification-gap lesson).

## Done criterion
Flat-shard-plan + world=1/replicated bit-exact parity + **reduced-gradient == full-batch gradient
(teeth)** + partition loss-curve tracking + determinism gates green; clippy/fmt clean; observed
partition divergence recorded. A ZeRO-3/FSDP layer over the simulated `ProcessGroup` whose *gradient*
provably matches a single-process reference (and whose loss curve tracks it) — the substrate 0016's
distributed checkpoint/resharding builds on. Ships on the `0.5.x` line.
