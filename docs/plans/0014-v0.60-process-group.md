# 0014 — `ProcessGroup` trait + thread-simulated multi-rank backend (serves: v0.60 / ADR 0008)

## Goal

The ADR-0008 collective-correctness gate, fully reachable on one machine: a `ProcessGroup` trait
(the collective abstraction the real `cudarc::nccl` backend implements at the 0017 wall) plus a
**thread-simulated** N-rank backend with **deterministic** collective math — so the load-bearing
gate, *all-reduced gradients == a single-process summed reference*, goes CI-green with no second GPU.

**Success:** `cargo test -p tritium-train` green incl. the collective gates (all_reduce ==
single-process reference, reduce_scatter / all_gather / broadcast, determinism under thread
scheduling, length-mismatch errors); `clippy -D warnings` + `fmt --check` clean.

## Where it lives (infancy / minimal-clean)

In **`tritium-train`** as a `dist` module — *not* a new crate. The trait + the simulated backend are
pure CPU (`#![forbid(unsafe_code)]`), and the collectives serve training (gradient reduction, param
gather) which already lives here alongside the [`DataSampler`](../../crates/tritium-train/src/data.rs).
0015 (ZeRO-3/FSDP over the simulated PG) layers on top here; the real NCCL backend (0017, behind the
wall) implements the same trait from `tritium-cuda` (cuda-gated). If `dist` grows, promoting it to a
`tritium-dist` crate is a cheap code-move later — nothing here makes that expensive.

## Design

- **`ReduceOp`**: `Sum` | `Avg` (the two data-parallel/FSDP needs — gradient sum, gradient average).
- **`DistError`**: `LengthMismatch { expected, got }` (a collective got mis-sized buffers — returned,
  never panicked, mirroring the crate's never-panic discipline) | `Backend(String)` (a real backend
  failure; unused by the sim, the seam `cudarc::nccl` needs at 0017).
- **`ProcessGroup` trait** (`rank`, `world_size`, and the four collectives, each `-> Result<(),
  DistError>`):
  - `all_reduce(&self, buf: &mut [f32], op)` — every rank ends with the reduction over all ranks.
  - `reduce_scatter(&self, input: &[f32], output: &mut [f32], op)` — `input.len() == world *
    output.len()`; rank `r` ends with the reduction of the `r`-th chunk across ranks.
  - `all_gather(&self, input: &[f32], output: &mut [f32])` — `output.len() == world * input.len()`;
    every rank ends with all ranks' inputs concatenated in rank order.
  - `broadcast(&self, buf: &mut [f32], root)` — every rank ends with `root`'s buffer.
- **`SimProcessGroup`** — the "gloo-for-CI" pattern. `SimProcessGroup::world(n) -> Vec<_>` hands back
  `n` handles sharing one `Arc<SimShared>` (per-rank staging `Vec`s behind a `Mutex` + a
  `std::sync::Barrier(n)`); each handle is moved into its own thread. A collective = *publish my
  contribution to slot[rank] → barrier → read all slots and combine → barrier* (the second barrier
  fences slot reuse for the next collective). **Determinism:** every reduction folds the slots in a
  **fixed rank order `0..world`**, so the result is independent of thread scheduling and bit-identical
  to a single-process reference that folds in the same order (f32 add is non-associative — fixed order
  is the whole point).

## Gates
- **all_reduce == reference:** `world∈{1,2,4,8}`, random per-rank f32 vectors; each rank's `all_reduce`
  result is **bit-exact** to `Σ_{r=0..world} v_r` folded in rank order; every rank agrees. `Avg` = that
  `/ world`.
- **reduce_scatter / all_gather / broadcast:** match their single-process references (scatter = ordered
  chunk reductions; gather = ordered concat; broadcast = root's buffer to all).
- **determinism:** repeating a collective many times across freshly-scheduled threads yields the
  identical bit pattern (no scheduling dependence).
- **errors:** mis-sized buffers → `Err(LengthMismatch)`, never a panic / OOB.

## Design notes
- Contract (documented): all ranks must invoke the same collective sequence (as real MPI/NCCL) — the
  paired barriers assume lockstep. A mismatch is a caller bug.
- The fixed-order fold is the bridge to 0015's loss-parity gate and to the 0017 NCCL wire-correctness
  check (both compare against this deterministic reference).

## Done criterion
Collective gates + determinism + error gates green; clippy/fmt clean. A `ProcessGroup` trait with a
deterministic thread-simulated backend — the substrate 0015's ZeRO-3/FSDP and 0017's NCCL backend
share. Ships on the `0.5.x` line.

## Outcome — shipped `v0.5.4` (CPU sim)

`ProcessGroup` (object-safe) + `ReduceOp` + `DistError` + the thread-simulated `SimProcessGroup`
landed in `crates/tritium-train/src/dist.rs`; **14 collective-gate tests** green
(`crates/tritium-train/tests/dist_collectives.rs`), in-scope `clippy -D warnings` + `fmt` clean.

**Gates met.** all_reduce == single-process summed reference, bit-exact, `world∈{1,2,4,8}` (+ a
proptest over `world∈[1,8]`, `n∈[1,40)`); reduce_scatter (ordered chunk reductions) / all_gather
(ordered concat) / broadcast (root → all) each match their single-process reference; `Avg` =
`Sum/world` for all_reduce **and** reduce_scatter; **determinism** under thread scheduling proven for
all four collectives by 40–50× rerun bit-identity; mis-sized buffers → `Err`, never a panic.

**Adversarial review hardened the barrier protocol (the load-bearing fix).** A 10-lens fleet
confirmed the first cut had a real **deadlock**: `reduce_scatter`/`all_gather`/`broadcast` did a local
size/root pre-check and `return Err(..)` *before* `publish()`/barrier #1, so a size-disagreeing rank
did **zero** `barrier.wait()` calls while its peers blocked at barrier #1 forever (a CI hang, not a
clean failure) — only `all_reduce` was immune (it published first). Fix: **every collective is now
"publish first → validate after barrier #1 → ALWAYS reach barrier #2"**, the uniform invariant *every
collective performs exactly two `barrier.wait()` calls on every code path, Ok or Err*. A new
timeout-guarded multi-rank regression test (`reduce_scatter_size_disagreement_does_not_deadlock`,
detached threads + `recv_timeout`) **provably hangs→fails against the old code** and passes in 0.04 s
against the fix.

**Beyond the original plan (review-driven, minimal):** a per-collective **op-tag** checked after
barrier #1 turns a cross-collective desync (ranks calling *different* collectives at the same step)
into a clean symmetric `DistError::CollectiveMismatch` instead of garbage/hang
(`divergent_collectives_return_clean_mismatch_no_hang`); a dedicated `DistError::LengthOverflow`
replaces the dishonest `usize::MAX` sentinel on `world*chunk` overflow.

**Documented limitations of the CI sim (accepted, not re-architected):** `std::sync::Barrier` has no
break/poison, so a rank that *panics* inside a collective (a contract violation under the never-panic
discipline) strands its peers; and ranks calling a *different number* of collectives is an uncatchable
count mismatch (the op-tag guard only catches same-step type/order divergence). Both are stated in the
module doc — the real NCCL backend (0017) brings its own timeout/abort. Next: 0015 ZeRO-3/FSDP over
this `ProcessGroup`.
