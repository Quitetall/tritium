# 0017–0018 — Real NCCL backend + 2-GPU parity (the ≥2-GPU wall; serves: v0.60 → tag `v0.60.0`)

## Goal

Clear the two ADR-0008 gates that genuinely need a second GPU, in one rented session:
- **0017 — real-NCCL wire-correctness:** `cudarc::nccl` collectives (all_reduce / reduce_scatter /
  all_gather / broadcast), one rank per GPU, validated against the deterministic simulated reference
  (0014). NCCL ring/tree reductions reorder float adds, so the match is **within a tolerance**, like the
  0015 data-parallel gate (not bit-exact).
- **0018 — 2-GPU FSDP loss-parity:** the *same* tiny-MLP FSDP loop the sim proved correct (0015), run
  over the real `NcclProcessGroup` across the box's GPUs, with the loss curve tracking a single-process
  reference. Tag **`v0.60.0`** when both pass.

## What is already done (this machine) vs the box

The backend + gates are **written and verified on the single 4090** — only the ≥2-rank reduction values
need the second GPU:
- **`tritium-cuda::nccl`** (`NcclProcessGroup`, behind the `nccl` feature → adds cudarc's `nccl` =
  NCCL-2.30 bindings): implements the same `tritium_train::dist::ProcessGroup` trait as the sim, so the
  FSDP loop (0015) and DCP (0016) run over it unchanged. Compiles + links real libNCCL locally.
- **Verified on the 4090 (`world=1`):** all four collectives + the size-contract errors run, and the
  **full FSDP training loop runs over NCCL bit-exact to the single-process reference**
  (`nccl_fsdp_loss_parity world=1: bit-exact`).
- **Self-skipping `world>=2` gates** (`nccl_all_reduce/all_gather/broadcast_..._multi_gpu`,
  `nccl_fsdp_loss_parity`): compile + skip on one GPU, **activate automatically on ≥2 GPUs**.

So the rented session is *clone → build → run* — no code authored under the clock.

## Box requirements (preflight — `scripts/gpu_session.sh` checks these first)

| Need | Why | If missing |
|------|-----|-----------|
| **CUDA 13.x toolkit (`nvcc`)** | `build.rs` compiles the PTX offline via nvcc; cudarc is pinned to `cuda-13020` (valid on 13.x driver only) | **fallback:** flip `cuda-13020` → the `cuda-12xxx` matching the box (e.g. `cuda-12060`) in `crates/tritium-cuda/Cargo.toml` |
| **NCCL ≥ 2.30** (`libnccl.so.2`) | cudarc's `nccl` feature binds `nccl-02030` | **fallback:** set the `nccl` feature to the matching `cudarc/nccl-02018`..`02029` |
| **≥2 GPUs, ideally NVLink** | the wall gates | scaling is meaningless at tiny scale anyway (see below) — PCIe is fine for the correctness gates |
| **Rust 1.89** | workspace MSRV | `rustup default 1.89` |

PTX is emitted at `compute_75`/`compute_80` and JITs up to the device SM at load, so **no per-arch
rebuild** is needed — sm_80 (A100) / sm_90 (H100) are covered by the same build.

Version-pin notes (the preflight prints the exact fallback pin if it trips): the cudarc `cuda-12xxx` /
`nccl-020xx` feature pins are **sparse** — there is no `cuda-12070` (use `cuda-12060` for 12.6/12.7) and
no `nccl-02023` (use `nccl-02022`). NCCL **> 2.30** is generally 2.x-ABI-safe but the bindings stay
pinned at 2.30, so the preflight only enforces the `>= 2.30` lower bound.

## Honest scope: the ≥80% scaling gate

The 0015/0017/0018 models are **tiny seeded MLPs** — comms are negligible, so a throughput-scaling
number from them is trivially ~100% and proves nothing. A *meaningful* ≥80% scaling measurement needs a
model large enough that comms matter, which is the **deferred 2B resident-training engine** (fenced in
0013). So this session clears the **correctness wall** (0017 wire-correctness + 0018 loss-parity); the
real-scale throughput-scaling gate stays explicitly deferred (or needs a mid-size model = more prep +
more GPU hours). `v0.60.0` is tagged on correctness; the ADR's ≥80% line is annotated as deferred.

## Session runbook (`scripts/gpu_session.sh`, time-boxed)

1. **Preflight (~10 min):** assert CUDA 13.x + NCCL ≥2.30 + nvcc + 2 GPUs (`nvidia-smi topo -m` records
   the interconnect). If CUDA ≠ 13.x or NCCL < 2.30, apply the documented feature flip *before*
   building (don't debug launch errors later).
2. **Build (~15 min):** `cargo build -p tritium-cuda --features cuda,nccl --release`.
3. **1-GPU warm-up (cheap, high-value):** full `tritium-cuda --features cuda` suite +
   `compute-sanitizer` on the datacenter arch — re-verifies the IMMA/decode/backward PTX off the 4090
   for the first time. (Also confirms the cudarc `cuda-13020` pin works on a non-4090 13.x driver.)
4. **0017 wire-correctness:** `cargo test -p tritium-cuda --features nccl --lib nccl::` — the
   `*_multi_gpu` gates now run (world = device count).
5. **0018 loss-parity:** `nccl_fsdp_loss_parity` runs at world ≥ 2; record the printed `max |Δloss|`
   and tighten the gate's tolerance to it for the committed result.
6. **Capture + commit results** (`gpu-results/` → a `gpu-run-<date>` branch, pushed), then **tag
   `v0.60.0`** if 0017 + 0018 pass, push, and **terminate the box.** The script's verdict requires
   *positive* multi-GPU evidence (a real `..._multi_gpu ... ok` + `world>=2` line, non-zero cargo exit →
   FAIL, gates `timeout`-wrapped so a deadlocked rank fails fast) — it will not print PASS unless a real
   2-GPU run happened. **Before tagging:** the 0018 loss-parity tolerance is a loose placeholder (the
   loss curve is scale-invariant under AdamW, so it is a convergence check, not the reduce-op gate — that
   is the all_reduce *value* gate); read the printed `max |Δloss|`, tighten the bound to ~10× it, and
   re-run to confirm still-green before tagging.

## Gates
- **0017:** NCCL all_reduce(Sum) == single-process summed reference; all_gather == ordered concat
  (exact); broadcast == root's buffer (exact); within tolerance for the reductions. (world = device count.)
- **0018:** NCCL FSDP loss curve == single-process reference within the recorded tolerance (`world>=2`);
  `world=1` is bit-exact (verified locally). No NaN.
- **1-GPU re-verify (bonus):** the full CUDA suite + compute-sanitizer green on the datacenter arch.
