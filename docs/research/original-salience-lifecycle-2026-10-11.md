# Original forward-salience receipt contract

Implementation slice of the original-A recording/cold-replay amendment in
proposed ADR0064. This is **structural vocabulary and inspection only**, not an
executed producer, cold numerical replay, qualification or acceptance.

The new schema distinguishes complete all-token forward windows from staged-B
next-token loss/gradient capture. A one-token window is valid; the final token
contributes a row. Ordered operations bind shared projection inputs once, their
actual inverse-axis interpretations, channel counts and raw f64 moment content.
There is no invented loss, gradient, statistics-kind promotion or fake B stage.

The request carries complete sorted raw tensor/asset bindings, architecture and
original stored-byte identity. The typed view rederives that identity with the
existing shared function. Pair geometry uses the same private implementation as
the existing declared transform. No old profile or identity domain changes.

Logical caps cover raw source/assets, config, widened masters, contexts, tokens,
moments and private text/tokenizer config. Every cap is compared against explicit
receiver admission. Caps do not establish evidence/parser/tape/RSS/GPU limits;
asset digest metadata cannot prove an actual asset's byte length. Actual source
observation and producer preflight must enforce those bytes.

`OriginalSalienceCaptureView::fold` checks strict registered v1 payloads, one
standalone root, complete ordered inputs/outputs/counts and shared source identity.
A valid lone start yields no completed view. Unknown versions, orphan/duplicate,
mixed-root and malformed complete records reject. CLI `evidence verify/view`
recognizes the view through the shared implementation, not a second CLI schema.

Synthetic lifecycle tests demonstrate the distinction explicitly: replacing a
moment digest and rebuilding a valid hash chain remains structurally coherent.
Changing raw text without changing claimed tokens may also remain structurally
coherent. Neither establishes numerical truth. The next required execution slice
must derive this request from actual `ObservedWeightSource` and immutable
`SourceCalibrationModel`, use existing `Calib/accumulate` and shared taps, and
cold-replay actual original source/tokenizer/graph before comparing every binding.

Mandatory A-capture -> transform/staged-B -> captured-C carrier ancestry still
needs the subsequent serialized-contract amendment. Existing Declared semantics
remain unchanged. Complete graph families, CLI/quantize/Qwen/Python/HF surfaces,
both campaign migrations, SOTA/GPU/out-of-core/physical-device/quality/runtime/
bytes/reproduction and all full ADR0033 release obligations remain outstanding.

Verification is recorded from actual commands and frozen source evidence; no
test, gate or empirical success is asserted by this authored document.
