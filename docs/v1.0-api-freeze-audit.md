# v1.0 API + C-ABI Freeze-Readiness Audit

- **Status:** Report only — pre-freeze readiness assessment. **No public API is changed by this document.**
- **Date:** 2026-06-23
- **Workspace version:** `0.6.6` (the 0.6.x point-release line carrying the reachable v0.80/v0.90 work)
- **Relates:** [ADR 0012 — v1.0 Release](./adr/0012-v100-release.md) (the freeze milestone), [ADR 0011 — v0.90 Hardening](./adr/0011-v090-hardening.md) (the doc-coverage + semver baseline gates), [ADR 0010 — v0.80 Interop](./adr/0010-v080-interop.md) (the `tritium-ffi` C ABI), [ROADMAP](./ROADMAP.md).

## 0. Scope, method, and honesty boundary

ADR 0012 makes the v1.0 *tag* gated on fenced hardware Tritium does not have today: a
real-model fresh-env capstone (BitNet b1.58 2B4T download + GPU fine-tune/quantize at
real scale) and the full GPU CI matrix re-run on the release commit. **None of that is
done or claimed here.** This audit produces *only* the CPU/docs-reachable preparation
ADR 0012 calls for under its first exit gate — "`cargo-semver-checks` baseline set;
public API + C ABI frozen … contract test … cpu-only" — by inventorying the public
surface, flagging what should change *before* the freeze, and documenting the
enforcement process that locks at 1.0.

**This is a report. It mutates no crate API.** Sealing an enum, adding
`#[non_exhaustive]`, or removing a `pub` are themselves breaking changes that belong in a
separate, reviewed, version-bumped step (per `scripts/check-semver.sh`'s "pre-1.0 breaks
are *allowed* but must be deliberate" contract). Everything below is *flagged*, never
applied.

**Method.** The surface was read directly from each crate's `src/lib.rs` re-exports and
the modules behind them, cross-checked against the workspace manifest, the FFI header +
its drift test, `scripts/check-semver.sh`, and `.github/workflows/ci.yml`. Doc coverage
and the C-ABI drift gate were *measured locally*, not asserted — see §6.

## 2. Per-crate freeze-readiness

Legend: **Ready** = surface looks lockable as-is; **Needs-attention** = a specific item
to decide on before the freeze (each cross-referenced to the prioritized list in §7).

### tritium-core — **Ready**
Public surface: `Trit`, `DType`, `TernaryFormat`, `TritError`, `ScaleGranularity`,
`GemmShape`, `reference_mpgemm`, `absmean`, `TERNARY_IDEAL_BITS`. Exemplary for a
foundation crate: `#![forbid(unsafe_code)]`, `#![deny(missing_docs)]`, and every public
*enum* that can plausibly grow (`DType`, `TernaryFormat`, `ScaleGranularity`, `TritError`)
already carries `#[non_exhaustive]`. `GemmShape` is an all-`pub`-fields struct (`m,n,k`) —
intentionally a transparent value type; adding a field later would break, but `(M,N,K)`
geometry is fixed, so leaving it exhaustive is defensible. **No action required.**

### tritium-spec — **Ready**
Public surface: the `TernaryBackend` trait, the `DeviceBuffer` trait, `DeviceCaps`,
`BackendError`. `BackendError` is `#[non_exhaustive]`. The trait is *deliberately
object-safe* with a compile-time `_assert_object_safe` guard — freezing it locks that
guarantee. One thing to *note* (not change): `TernaryBackend` is a public trait with
default methods (`mpgemm_with_act_quant`, `as_any`), so post-1.0 you can *add* defaulted
methods additively but cannot add a *required* method without a major bump. That is the
correct trade and is already the shape it has. **No action required.**

### tritium-format — **Ready**
Largest data surface: GGUF reader/writer, safetensors, TQ1_0/TQ2_0 block + row pack,
SALT sidecar, SALT-in-GGUF, sparse planes, `.tqbin`/`.tqidx`, I2_S/IMMA conversion, plus
the magic/version constants for each container. `FormatError`, `GgufError`, `GgufValue`
are `#[non_exhaustive]`. **Needs-attention (minor):** `SafeTensorsError`
(`safetensors.rs:21`) and `PlaneRepr` (`sparse.rs:187`) are public enums *without*
`#[non_exhaustive]`. `SafeTensorsError` is an error type that will plausibly grow new
variants → flag as [breaking] §7. `PlaneRepr` is a closed dense/sparse storage-form switch
that is unlikely to gain a third arm; leaving it exhaustive is defensible but worth a
conscious decision. The committed magic/version `pub const`s (`SALT_VERSION`,
`TQBIN_VERSION`, …) are *values that must stay stable by definition* — freezing them is a
feature, not a risk.

### tritium-runtime — **Ready**
Public surface: `BackendEntry`, the `BACKENDS` distributed slice, `Registry`, `global`,
`init_global`. `BackendEntry` is an all-`pub`-fields struct (`name`, `init`) — but that is
*the registration ABI* downstream backends construct directly via
`#[linkme::distributed_slice(BACKENDS)]`, so its fields are intentionally public and
adding one would be breaking by design. This is the one place where an exhaustive public
struct is correct (a `#[non_exhaustive]` `BackendEntry` could not be constructed by
downstream crates). **No action required.**

### tritium-testkit — **Ready**
Public surface: `ConformanceVector`, `Tolerance`, `generate_vectors`, `save/load_vectors`,
`run_conformance`, `run_fused_fallback_contract`, the frozen-set accessors
(`frozen_vectors`, `FROZEN_SEED`, `FROZEN_COUNT`, `VECTOR_SET_VERSION`), `Report`,
`FailedCase`, `FailureReason`, `JsonlError`. `FailureReason` and `JsonlError` are both
`#[non_exhaustive]`. The reference backend is exported but `#[doc(hidden)]` and explicitly
"public only so this crate's own doctests have a known-good backend" — that is a
*deliberate, documented* leak for testing, not an accidental one. Worth confirming at
freeze time whether `#[doc(hidden)]` items are part of the frozen contract (cargo-semver
*does* track them); see §7. **No structural action required.**

### tritium-cpu — **Needs-attention (enforcement only)**
Public surface: `CpuBackend`, `CpuBuffer`, plus the trait impls. `CpuBuffer`'s field
(`bytes`) is *private*; the only accessor is `pub fn bytes(&self) -> &[u8]` — no leaky
internals. The kernel/SIMD modules (`kernel`, `simd::lut`, `simd::avx512`) are all
private. **The one gap is enforcement, not coverage:** the crate does *not* carry
`#![deny(missing_docs)]`, yet a local rustdoc run with `-W missing_docs` reports **zero
missing-doc warnings** (§6). So the surface *is* documented; it simply isn't *gated*. Flag:
add `#![deny(missing_docs)]` to lock that in before the freeze — **[additive]**, §7.

### tritium-quantize — **Ready**
Public surface: the SALT pipeline — `residual_expand`, `Plane`, `PlaneStack`, `allocate`,
`GroupInput`, `AllocConfig`, `Allocation`, `quantize_tensor`, `QuantConfig`,
`QuantizedTensor`, `ScaleGroup`, `Sensitivity`, and the `AllocError`/`QuantError` errors.
`#![deny(missing_docs)]` is on. **Needs-attention (minor):** `AllocError`
(`allocate.rs:79`), `QuantError` (`quantize.rs:124`), and the public config enums
`Sensitivity`/`ScaleGroup` are *not* `#[non_exhaustive]`. The two error enums are the
prime candidates to seal before the freeze (errors grow); `Sensitivity`/`ScaleGroup`
encode a fixed quantization taxonomy and may legitimately want to grow new modes post-1.0
→ flag all as [breaking] §7.

### tritium-nn — **Needs-attention**
Public surface: `ModelConfig`, `ModelRunner`, `ModelWeights`, `LayerWeights`,
`TransformerBlock`/`BlockScratch`/`BlockDump`, `TernaryLinear`, `DenseLinear`, `Relu2Mlp`,
`Projection`, `KvCache`, `Tokenizer`, `ForwardDump`, the ops (`gqa_attention`, `rmsnorm`,
`rope_apply`, `softmax_rows`, `sample_*`, `quantize_activation_int8`, `QB`),
`f16_bytes_to_f32`, `NnError`. Two issues:
1. **Not in the semver gate** (§7) — the script comment says the API "is still in flux
   during the perf/training work." For a v1.0 freeze it must either join the gate or be
   explicitly documented as a deliberately-unfrozen surface.
2. **`ModelConfig` (`config.rs:10`) is an all-`pub`-fields struct without
   `#[non_exhaustive]`.** Model architectures gain fields (sliding-window, MoE,
   per-layer overrides…); a frozen exhaustive `ModelConfig` cannot grow without a major
   bump. Strong [breaking] candidate → §7. `NnError` *is* `#[non_exhaustive]`.
3. `Projection` (`projection.rs:19`) is a public enum without `#[non_exhaustive]`; assess
   whether the projection taxonomy is closed.

Doc coverage: **0 missing-doc warnings measured** (§6) despite no `#![deny(missing_docs)]`
→ flag enforcement [additive] §7.

### tritium-train — **Needs-attention**
Largest functional surface, and the only crate exposing whole `pub mod`s
(`checkpoint`, `data`, `dcp`, `dist`, `fsdp`, `gradcheck`, `lora`, `lr`, `ops`, `optim`,
`tape`, `value`) rather than a curated re-export list. Issues:
1. **Not in the semver gate** ("still in flux during the … training work").
2. **`pub mod` everything** widens the frozen surface to *every* `pub` item inside those
   modules (not just the curated `pub use` list at the crate root). Before a freeze,
   decide whether each `pub mod` should become a private `mod` with a curated re-export
   (so internals can move post-1.0). This is the single biggest "accidental surface" risk
   in the workspace → §7 [breaking].
3. Error enums `CheckpointError`, `DcpError`, `DistError`, `FlatShardError`, and the
   `ReduceOp` enum are public *without* `#[non_exhaustive]` → seal the error enums
   [breaking] §7; assess `ReduceOp` (it mirrors a fixed NCCL collective set, so leaving it
   exhaustive may be fine).

Doc coverage: **0 missing-doc warnings measured** (§6) → flag enforcement [additive] §7.

### tritium-ffi — **Ready (C ABI; see §5 for the freeze statement)**
`#![deny(missing_docs)]`, `TRITIUM_ABI_VERSION = 1`, four exported `extern "C"` functions,
the `TritiumStatus` repr-C enum, the opaque `TritiumModel`. The committed
`include/tritium.h` is kept honest by the `header_is_current` drift test and validated as
C11 + C++17 by `header_compiles_as_c_and_cpp`. Both pass locally (§6). The Rust-visible
`TritiumStatus` enum is *not* `#[non_exhaustive]` — and for a C ABI that is **correct**: the
numeric discriminants are the wire contract; C consumers `switch` on them and a
`#[non_exhaustive]` Rust enum would not change the C side anyway. Adding a status code is
an additive ABI change (a new trailing variant), not a break. **No action required.**

### tritium-candle / tritium-burn / tritium-onnx — **Ready**
Each is a thin, feature-gated interop wrapper (`candle`/`burn`/`onnx` features, off by
default) around the same reference kernel. `tritium-burn` and `tritium-onnx` each carry a
`#[non_exhaustive]` error enum (`BurnTernaryError`, `OnnxTernaryError`); `tritium-candle`
returns candle's own `candle_core::Error` (no own enum). All three carry
`#![deny(missing_docs)]`. The op types (`TernaryMpGemm`, the ONNX op/kernel structs) are
the framework-required public shapes. Because they are *off by default*, they do not widen
the default `cargo build`/`cargo test --workspace` surface. **No action required**, beyond
deciding at freeze time whether the interop crates are part of the *frozen* set or a
"best-effort, may-track-upstream" tier (candle/burn/ort all move fast; pinning their semver
to Tritium's 1.0 couples Tritium's major version to theirs) → noted in §7.

### tritium-serve — **Needs-attention (minor)**
Public surface: the OpenAI DTOs (`ChatRequest`, `ChatMessage`, `ChatCompletion`,
`ChatChunk`, `Choice`, `Delta`, `Usage`, `ModelList`, `ApiError`, …), `ServeConfig`,
`GenRequest`, `Step`, `Sampling`, `FinishReason`, `GenError`, the `Generator` trait,
`MockGenerator`/`RunnerGenerator`, `IdPassthroughTokenizer`. `#![deny(missing_docs)]` is on.
The DTO structs are *deliberately* exhaustive public-field types — they mirror the OpenAI
wire schema, whose shape is externally fixed, so all-`pub`-fields is correct there. The
items to decide on are the *behavioral* enums: `Sampling`, `FinishReason`, and `GenError`
are public enums without `#[non_exhaustive]`. `GenError` is an error type that will grow →
[breaking] §7. `Sampling` is a strategy set that may gain modes → [breaking] §7.
`FinishReason` mirrors OpenAI's fixed `stop`/`length` (`content_filter`/`tool_calls` exist
upstream) — likely should be `#[non_exhaustive]` to absorb future OpenAI reasons →
[breaking] §7. Also decide whether `serve` (an application) is in the frozen library tier
at all.

### tritium-cli — **Ready (no library API)**
A binary (`tritium` with `inspect`/`list-backends`/`generate`). Per `check-semver.sh`,
binaries "have no library API to freeze." The CLI *invocation contract* (flags,
subcommands, output) is a separate UX-stability concern, out of scope for the API/ABI
freeze. **No library action.**

### tritium-cuda — **Fenced (deferred)**
Reads, but is excluded from every reachable gate: it needs `nvcc` + a GPU to build the
`cuda` feature (`check-semver.sh` excludes it for exactly this reason). It exposes a large
surface (`CudaBackend`, `CudaDecodeModel`, the `DecodeModelSpec`/`DecodeLayerSpec`/
`DecodeLinearSpec` builders, `SaltResidentLinear`, `BatchKv`, NCCL types, the `train.rs`
`SmokeConfig`/`SmokeReport`) and does *not* carry `#![deny(missing_docs)]`. **Its freeze
readiness cannot be honestly assessed or gated on CPU** — it belongs to the GPU/fenced
portion of ADR 0012 and is deferred there. Flagged as the single largest unaudited surface.

### tritium-wgpu / tritium-wasm — **Ready (reachable, but tests are environment-gated)**
Both carry `#![deny(missing_docs)]` and expose the standard backend pair
(`WgpuBackend`/`WgpuBuffer`, `WasmBackend`/`WasmBuffer`). wgpu's conformance test self-skips
with no Vulkan adapter (so it only *bites* on the 4090 lane); wasm runs under `wasmtime` on
the hosted `wasm` CI lane. Surfaces look lockable; their *correctness gates* are
environment-gated, not their APIs.

### tritium-py — **Needs-attention (enforcement only)**
A PyO3 `cdylib` (`name = "tritium"`). Its *Python* ABI is governed by PyO3/abi3 + maturin
(the v0.80 ffi/py work), not Rust `cargo-semver-checks`, so it is correctly outside the
Rust semver gate. The Rust side has **0 missing-doc warnings measured** (§6) but no
`#![deny(missing_docs)]` → flag enforcement [additive] §7. The *Python* surface
(`Model.load`, `Model.generate`, `ternary_matmul`) should get its own stability note in the
1.0 docs (Python signatures + exception types), tracked separately from the Rust freeze.

## 3. Summary of structural findings

- **Leaky/accidental `pub`:** none found that look unintentional. The transparent
  public-field structs (`GemmShape`, `BackendEntry`, the serve OpenAI DTOs, `ModelConfig`)
  are each *intentionally* exhaustive — but `ModelConfig` is the one whose externally-fixed
  shape argument is weak (architectures grow), so it is the strongest seal candidate.
  `tritium-testkit`'s reference backend is a *documented* `#[doc(hidden)]` test leak.
- **`pub mod` over-exposure:** **`tritium-train` exposes 12 whole `pub mod`s.** This is the
  largest accidental-surface risk: the frozen contract becomes every `pub` item in every
  submodule. Decide module-by-module before the freeze.
- **Enums that should likely be `#[non_exhaustive]` before the freeze but are not:**
  `SafeTensorsError`, `AllocError`, `QuantError`, `CheckpointError`, `DcpError`,
  `DistError`, `FlatShardError`, `GenError`, `Sampling`, `FinishReason` (and *assess*:
  `PlaneRepr`, `Projection`, `Sensitivity`, `ScaleGroup`, `ReduceOp`). The foundation
  crates (`core`, `spec`, `format`'s primary errors, `nn`'s `NnError`, `testkit`) already do
  this correctly; the gap is concentrated in `quantize`, `train`, and `serve`.
- **Doc enforcement gaps (coverage is already complete):** `tritium-cpu`, `-nn`, `-train`,
  `-py` lack `#![deny(missing_docs)]` but measured **0** missing docs. Adding the lint is
  additive and locks coverage in. `tritium-cuda` is unmeasured (fenced).

## 4. C-ABI freeze confirmation

The `tritium-ffi` crate is the v1.0 C-ABI surface. Read directly:

- **Versioned at ABI v1.** `pub const TRITIUM_ABI_VERSION: u32 = 1;` in `src/lib.rs`,
  mirrored as `#define TRITIUM_ABI_VERSION 1` in the committed `include/tritium.h`, exposed
  at runtime via `tritium_abi_version()`. The `abi.rs` test
  `abi_version_matches_constant` asserts the constant, the function, and the literal `1` all
  agree.
- **The exported surface is four functions + one repr-C enum + one opaque handle:**
  `tritium_abi_version`, `tritium_version`, `tritium_model_load_file`, `tritium_generate`,
  `tritium_model_free`; `TritiumStatus` (`Ok=0`, `NullArg`, `Load`, `Generate`,
  `BufferTooSmall`, `Panic`); opaque `struct TritiumModel`. That is the entire wire contract.
- **The header cannot silently drift.** `tests/header.rs::header_is_current` regenerates the
  header with `cbindgen` from the live source and `assert_eq!`s it against the committed
  `include/tritium.h`, printing the exact regenerate command on mismatch.
  `header_compiles_as_c_and_cpp` compiles it under `cc -std=c11` and `c++ -std=c++17` with
  `-Wall -Wextra -fsyntax-only`. Both pass locally (§6).
- **Panic = abort contract.** `[profile.release]`/`[profile.dist]` in the workspace manifest
  set `panic = "abort"`, so an internal panic aborts the process (the defined outcome) rather
  than unwinding across the `extern "C"` boundary (which is UB). The `catch_unwind` guards in
  every entry point additionally convert a panic into `TritiumStatus::Panic` *when built with*
  `panic = "unwind"` (the `dev`/`test` default). Every pointer argument is null-checked before
  any deref. `TritiumModel*` is `Send` but **not `Sync`** (documented).

**Freeze statement.** *At v1.0 the Tritium C ABI is frozen at `TRITIUM_ABI_VERSION = 1`.*
The frozen contract is: the five exported symbols and their signatures, the `TritiumStatus`
numeric discriminants (`Ok = 0`, errors non-zero), the opaque-handle ownership model
(`load` → owned handle → `free`), the null-checked / no-unwind boundary, and the
`Send`-not-`Sync` threading rule — exactly as captured in `include/tritium.h`.

**What a future ABI break requires.** Any change that alters an existing exported symbol's
signature, renumbers an existing `TritiumStatus` discriminant, changes the ownership/threading
contract, or removes a symbol is an **ABI break** and requires **bumping
`TRITIUM_ABI_VERSION` to 2** (and a Tritium major-version bump). The drift test will fail until
`include/tritium.h` is regenerated, forcing the header to track the change. *Additive* changes —
appending a new `extern "C"` function, or adding a new *trailing* `TritiumStatus` variant — are
ABI-compatible at v1 (existing callers keep working) and do **not** require bumping
`TRITIUM_ABI_VERSION`, though they should bump the crate's minor version. C consumers should
gate behavior on `tritium_abi_version()` at load time, not assume a specific build.

## 5. Post-1.0 freeze enforcement process

Two independent gates, both already wired into `.github/workflows/ci.yml`:

**Rust API — `cargo-semver-checks` (the `semver` CI lane).** `scripts/check-semver.sh` runs
`cargo semver-checks --baseline-rev <BASELINE>` over the stable, GPU-free library crates:
`-core`, `-spec`, `-format`, `-runtime`, `-cpu`, `-quantize`, `-testkit`. The baseline today
is the latest `v0.5.*` tag reachable from HEAD (the script's `git describe --match 'v0.5.*'`
resolves to `v0.5.10` on this tree). The lane uses `fetch-depth: 0` so the baseline tag is
available. Pre-1.0 the gate's contract is *"breaks are allowed but must be deliberate"* — it
surfaces an unintended break so a reviewer signs off and bumps the version.

*What locks at 1.0.* On tagging `v1.0.0`, the freeze flips this contract: the baseline becomes
`v1.0.0` and any **major**-level finding (a breaking change) **fails the lane** rather than
merely flagging it. Per ADR 0012's first exit gate, the `cargo-semver-checks` baseline is
*captured* at the release commit and the public API is declared frozen against it. The crate
list in `check-semver.sh` should be **widened before the freeze** to cover every crate whose
library API is meant to be frozen — concretely `tritium-nn` and `tritium-train` must be added
(or explicitly documented as an unfrozen tier; see §7), since the script comment currently
excludes them as "in flux."

*How a deliberate break is handled post-1.0.* A breaking change requires a **major version
bump** (`2.0.0`); the reviewer re-captures the baseline at the new major tag. There is no
mechanism (nor should there be) to wave a break through at the same major version — that is the
whole point of the freeze.

**C ABI — the cbindgen drift test + `TRITIUM_ABI_VERSION`.** Independent of `cargo-semver-checks`
(which checks Rust, not C). `tests/header.rs` runs on every platform in the `cpu-only-green`
lane (it is a normal `cargo test`), so any change to the exported C surface that is not
mirrored into `include/tritium.h` fails CI. Bumping `TRITIUM_ABI_VERSION` is the deliberate
signal for a C-ABI break (§4).

**Adjacent gates that re-run on the release commit (already present):** `publish-check`
(`cargo package --workspace`), `cargo-deny` (licenses + advisories + bans), `sbom` (CycloneDX),
and the `docs` dead-link lane. These are packaging/supply-chain hygiene, not API freeze, but
ADR 0012 re-runs "every prior milestone gate on the release commit."

**Fenced / not reachable on CPU:** the full GPU CI matrix re-run, `compute-sanitizer` over the
whole suite, multi-GPU NCCL parity, the Metal/ROCm platform lanes, and the real-model fresh-env
capstone (BitNet b1.58 2B4T download + GPU fine-tune/quantize). The `gpu`, `perf-regression`,
`wgpu`, and `serve-e2e` lanes are all `if: ${{ false }}` pending a self-hosted GPU runner. **The
v1.0 *tag* cannot be cut until those run green; this audit does not and cannot substitute for
them.**

## 6. Verified locally

All on this worktree at `0.6.6`, toolchain `cargo 1.96.0` / `cargo-semver-checks 0.48.0`:

- **C-ABI drift + compile gate.** `cargo test -p tritium-ffi` → **12 pass, 1 ignored**
  (the ignored one is the gated real-model round-trip needing `TRITIUM_FFI_MODEL`).
  `header_is_current` (cbindgen drift) and `header_compiles_as_c_and_cpp` (C11 + C++17) both
  pass. `abi_version_matches_constant` confirms `TRITIUM_ABI_VERSION == 1`.
- **Rust API stability gate.** `./scripts/check-semver.sh` ran the full
  `cargo-semver-checks` over all 7 gated crates against baseline `v0.5.10`, each reporting
  **"no semver update required"** (e.g. `tritium-core/-spec/-format/-runtime/-cpu/-quantize/
  -testkit`, 253 checks each). This confirms the enforcement mechanism works end-to-end and
  that the stable surface has no unintended break vs the baseline.
- **Doc-coverage measurement (the load-bearing honesty check).** `RUSTDOCFLAGS="-W
  missing_docs" cargo doc --no-deps -p <crate>` reported **0** "missing documentation for"
  warnings for each of `tritium-nn`, `tritium-train`, `tritium-cpu`, and `tritium-py` —
  the four library crates that do *not* carry `#![deny(missing_docs)]`. So the §2 claim that
  their gap is *enforcement, not coverage* is measured, not assumed. (rustdoc did surface a
  handful of unrelated intra-doc-link nits in `-cpu`/`-train`, none of which are missing-doc
  findings.)

**Not verified here (out of CPU scope):** `tritium-cuda`'s surface and docs (needs nvcc + GPU);
the GPU/multi-GPU/Metal/ROCm matrix; the real-model capstone. These are the fenced portion of
ADR 0012 and are explicitly deferred.

## 7. Prioritized pre-1.0 API changes to consider

Ordered by freeze impact. Each is **flagged only** — applying any of these is a separate,
reviewed, version-bumped change (and the [breaking] ones will themselves trip the semver gate,
which is the intended signal).

**P0 — decide the frozen tier + close the biggest accidental surface**
1. **[breaking] `tritium-train`: convert the 12 `pub mod`s to private `mod` + curated
   `pub use`.** Freezing whole modules freezes every `pub` item inside them. Curate the
   re-export list (the crate root already re-exports the intended types) so internals can
   evolve post-1.0. Largest accidental-surface risk in the workspace.
2. **[process] Decide each crate's freeze tier** and widen `scripts/check-semver.sh`
   accordingly: add `tritium-nn` and `tritium-train` to the gate (or document them as a
   deliberately-unfrozen tier); decide whether the feature-gated interop crates
   (`candle`/`burn`/`onnx`) and `serve` are *frozen* or *best-effort track-upstream* (their
   upstreams move fast — coupling Tritium's 1.0 to theirs is a real cost). `tritium-cuda`'s
   freeze is deferred to the GPU portion of ADR 0012.

**P1 — seal error enums that will grow (each [breaking])**
3. **[breaking]** Add `#[non_exhaustive]` to the public *error* enums currently missing it:
   `SafeTensorsError` (format), `AllocError` + `QuantError` (quantize), `CheckpointError` +
   `DcpError` + `DistError` + `FlatShardError` (train), `GenError` (serve). This lets each
   grow a new variant post-1.0 without a major bump — the same protection `core`/`spec`/
   `format`'s primary errors and `NnError` already have.

**P2 — seal config/strategy types whose shape will grow (each [breaking], assess case-by-case)**
4. **[breaking] `tritium-nn::ModelConfig`: add `#[non_exhaustive]`.** All-`pub`-fields struct;
   model architectures gain fields. Strongest non-error seal candidate.
5. **[breaking] `tritium-serve`: `Sampling` + `FinishReason` → `#[non_exhaustive]`.**
   `FinishReason` mirrors OpenAI, which has more reasons than `stop`/`length`; `Sampling` may
   gain modes.
6. **[breaking] (assess) `tritium-quantize::Sensitivity`/`ScaleGroup`,
   `tritium-format::PlaneRepr`, `tritium-nn::Projection`, `tritium-train::ReduceOp`.**
   Each is a taxonomy enum — decide whether it is genuinely *closed* (then leave exhaustive,
   document the decision) or may grow (then `#[non_exhaustive]`). `ReduceOp` mirrors a fixed
   NCCL collective set and is likely fine exhaustive.

**P3 — lock doc coverage (each [additive], zero current coverage gap — see §6)**
7. **[additive]** Add `#![deny(missing_docs)]` to `tritium-cpu`, `tritium-nn`,
   `tritium-train`, and `tritium-py`. Measured 0 missing docs today; the lint just prevents
   regression and makes the doc-coverage gate uniform across the frozen set. Audit
   `tritium-cuda`'s docs when the GPU lane is available.

**P4 — confirm intentional, documented decisions (no change, just sign-off)**
8. **[none]** Keep `GemmShape`, `BackendEntry`, and the serve OpenAI DTOs exhaustive — each is
   an intentionally-transparent value type or an externally-fixed wire schema. `TritiumStatus`
   stays a plain (non-`#[non_exhaustive]`) repr-C enum — for a C ABI the numeric discriminants
   are the contract and a trailing variant is additive (§4). Confirm whether `tritium-testkit`'s
   `#[doc(hidden)]` reference backend is part of the frozen contract (cargo-semver tracks
   `#[doc(hidden)]` items) or should be moved behind a `cfg`/test-only seam.
